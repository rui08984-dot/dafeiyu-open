# ADR-011：目标栈与决策节拍 —— 规则管「做不做」，LLM 管「下一步」，30s 定向不进帧循环

**Status:** Proposed（2026-11-18，待用户拍板）
**Date:** 2026-11-18
**Deciders:** 用户（产品方向：她能否自己开长任务）· 本轮调研（技术）
**相关:** ADR-001（进程分层）· ADR-003（先规则后学习）· ADR-004（世界感知与推理成本）· ADR-006（planner 分层）· ADR-007（验证与恢复）· ADR-010（记忆 v2）

## Context

ADR-006 已经解决了「一次任务里的计划放哪」：计划对象进宿主插件、差分注入、只在首次/失败/偏离时调 LLM。
它没有回答的是**跨轮、跨小时的问题**：

- 谁决定「现在要不要开始做一件事」？
- 做到一半用户去玩游戏了，她是继续、暂停、还是放弃？
- 用户三天前说「周末提醒我听新曲子」，这个意图存在哪、什么时候被翻出来？
- 任务做到第 12 步，预算还剩多少、是不是该停？

现状是**没有目标态**：所有意图都活在当轮上下文里。后果可观测：
用户离开后她不会继续；跨轮任务一断就丢；30 轮上限是唯一的停止机制；「她主动想做点什么」只能表现为一次发言，不能表现为一串动作。

外部最贵的教训来自 AutoGPT / BabyAGI：
- BabyAGI 的原始实现就是「无限循环：取任务→执行→生成新任务」，README 自己写明「infinite loop」「continuous 运行 = 高 API 消耗」
  （`yoheinakajima/babyagi_archive` 的 `README.md:44`、`:100-102`，本轮经 raw 抓取核对；当前 `babyagi` 主仓已改为 functionz 框架）；
- AutoGPT Classic 官方 README 已标「unsupported，实验结束」，issue #1994「Gets stuck in a loop」、#12499 最终加了「无限工具重试熔断」
  （`classic/README.md`、GitHub issues）；
- 两者共同的病根：**「要不要继续/算不算完成」由模型自己说**，没有外部判据，也没有预算真值。

三条既有红线仍然压着：
- ADR-004：>5ms 的推理不进帧循环；任何「每轮都不同」的内容不进前缀；
- ADR-001：`pet-core` 无状态，不做调度与决策；
- ADR-003：先规则后学习——目标选择在数据攒够之前不该上模型。

## Decision

**目标栈由新宿主插件 `mind-kernel` 持有；决策分两层：规则决定「做不做/停不停」，LLM 决定「下一步做什么」。
定向节拍 30s，只在有目标时跳；没有目标时完全事件驱动，0 成本。**

### 1. 目标对象与栈

```
goal = {
  id, text,
  source: 'user' | 'open_loop' | 'curiosity',
  status: 'queued' | 'active' | 'paused' | 'done' | 'failed' | 'abandoned',
  done_when: OracleRef,                 // 必填；没有就只能当 note
  budget: { maxSteps, maxWallMs, maxLlmCalls },
  risk: 'low' | 'medium' | 'high',
  plan_id, evidence: [], created_at, last_decision_at, reason
}
```

- 位置：`live-2d/plugins/community/mind-kernel/`，与 `world-sense`、`dispatch` 同级；**不新建进程/端口**。
- 上限：**1 个 active + 3 个 queued**。超出的排队或丢弃，不并发执行——并发是误伤与死循环的放大器。
- 持久化：`data/goals.json` 原子写（tmp+rename），每完成一个子任务 checkpoint 一次；
  重启后 `active` 一律降为 `paused`，**不自动续跑有副作用的动作**，等下一次定向重新验证后再继续。

### 2. 目标准入闸（五条，缺一不可）

1. `done_when` 指向 T2/T3 oracle（ADR-007）；**前台用户发起**的目标允许 `user_confirm`（结束时问一句，用户确认才算完成），
   但**后台/自主目标不允许** `user_confirm`——必须有外部状态或可交付产物。没有可验证条件的 goal 只能当 `note`，
   允许提醒、不允许自主执行。
2. `budget` 至少填两项；默认 `maxSteps=20`、`maxWallMs=10min`、`maxLlmCalls=4`。
3. `risk`：`high`（删除/覆盖/支付/权限）必须 `ask_user` 确认；`medium` 只允许可逆动作；`low` 可直接做。
4. 与当前 active goal 的 intent key 不重叠；重叠则合并，不新开（复用 `dispatch/index.js:992` 的意图去重）。
5. 来源是 `user` 或到期的 `open_loop`。`curiosity` 默认**关闭**；开启时只读、每小时 ≤1 次、必须走 `speech-budget`。

**为什么把「没有 oracle 就不许自主执行」写成硬闸**：这是 AutoGPT 式跑偏的根。模型可以提出一万个「下一步」，
但只有能被外部状态验证的目标才值得占预算。

### 3. 决策分层与节拍

| 层 | 只做 | 绝不做 | 节拍 |
|---|---|---|---|
| `mind-kernel`（规则） | 目标打分、准入、预算、活动门、熔断状态、pause/resume/abandon | 调 LLM、改 plan 内容、执行动作 | 30s（有 goal 时）+ 事件 |
| `dispatch/plan-store`（ADR-006） | 持有 plan、diff、状态机 | 调 LLM 做规划、等模型 | 每轮（纯函数） |
| 现有 LLM 循环 | 消费计划行，产出下一步工具调用 | 决定目标生死、维护预算真值 | 每轮 |
| 规划调用（同一个 client） | 首次分解 + 失败重规划 | 每步都调、输出 DAG | 首次/失败/偏离 |
| `pet-core` | 无 | 任何 goal/plan 状态 | — |

**30s 定向 tick 的具体检查项**（纯 JS，目标 <1ms）：

1. 当前 goal 是否还有 `budget`；超了 → `failed` + 写 task-episode；
2. 活动状态是否变成 `gaming/watching/away`；是 → 在**安全点**（子任务之间，绝不中途）`paused`；
3. 是否连续 `suspected_noop` 或循环三元组（ADR-007 熔断）；是 → 升级恢复或 `ask_user`；
4. 是否有到期的 `open_loop`；有 → 入队（不抢占用户当前对话）。**提醒频率仍受 ADR-010 约束**：
   TTL 7 天、最多 1 次/天、只在 `working/idle`，`gaming/watching/away` 一律不打扰；
5. 队列里是否有比当前更高优先级的 goal；有 → 当前 `paused`、新的 `active`（只在安全点切换）。

**为什么是 30s**：任务级决策的物理延迟是秒级；1s 重复判断会与世界采样抢节拍、制造抖动，也让日志无法读。
**为什么不是固定 cron**：用户作息不固定（ADR-010 同款理由）；没有 goal 时定时器空转是纯浪费。
**为什么不在 tick 里调 LLM**：一次 tick 就是一次 API 调用的话，一天 2880 次——这正是 BabyAGI 的账单。

### 4. 抢占与安全点

优先级：**用户当前消息 > 到期 open_loop > 进行中 goal > curiosity**。

- 用户说话：当前 goal 立即 `paused`（不 abort），对话主链优先；用户明确说「别弄了」才 `abandoned`。
- 用户在游戏中：自主 goal 在下一个安全点暂停；用户显式要求的 goal 继续，但表达层静音。
- 切换 goal 只能在安全点：一个动作发出后、T1 验证完、没有未决的写操作。
- `ask_user` 是正式状态，不是异常：问题、选项、超时（默认 5 分钟）都记进 goal.evidence。

### 5. 终止条件（必须显式，不许靠「模型不说话了」）

满足任一即结束，并写 task-episode：

1. T3 oracle 判成功；
2. `budget` 耗尽；
3. 连续 2 次重规划仍失败（ADR-007 第 4 档 → `ask_user`，仍无解则 `failed`）；
4. 循环熔断（同一 `(action,target)` 第 3 次）；
5. 用户 `abandoned`；
6. 目标前提消失（oracle 的 getter 读到「目标已不存在」，如文件被用户删了）。

**为什么把「前提消失」单列**：长任务跨小时，世界会变；继续执行一个已经不成立的目标，比失败更伤。

## Options Considered

### Option A（选中）：宿主插件持目标栈 + 30s 规则定向 + 事件驱动
| 维度 | 评估 |
|---|---|
| 实现 | 中（goal schema、原子写、规则评分、暂停/恢复状态机，约 300–400 行 JS） |
| 延迟 | 用户路径 0（事件驱动）；自主续跑最多 30s 延迟 |
| LLM 成本 | 定向 0 次；规划仍按 ADR-006 的 3 个触发点 |
| 崩溃半径 | goal 丢了只影响自主任务，不影响对话主链 |
| 前缀缓存 | ✅ 目标行只进易变尾巴，且只在变化时 |

**Pros**：不新增进程/端口；预算/步数/活动状态都是代码真值；可单测（打分与状态机是纯函数）；
与 ADR-006/007/010 全部接得上。
**Cons**：规则打分在 v1 一定很笨（只能靠 user/open_loop 两类来源兜住）；30s 心跳有最多半分钟延迟；
持久化与真实桌面可能不同步，恢复时必须重新观测。

### Option B：常驻自主循环（AutoGPT/BabyAGI 原样）
| 维度 | 评估 |
|---|---|
| 实现 | 低（一个 while + 任务生成） |
| 终止 | ❌ 靠模型说「完成」或永不停 |
| 成本 | ❌ 无上界；BabyAGI README 自己警告高 API 消耗 |
| 安全 | ❌ 无预算、无 oracle、无安全点 |

**Pros**： demo 观感强，能连续动。
**Cons**： **AutoGPT 已官方退役、BabyAGI 归档**；我们复盘文档也定过性：没有外部判据的「继续」就是烧钱和跑偏。**否**。

### Option C：固定 cron（每 10 分钟跑一次目标检查）
| 维度 | 评估 |
|---|---|
| 实现 | 最低 |
| 时机 | ❌ 用户不在/在游戏时照样触发；在忙时又错过 |
| 成本 | 固定尖峰，且大部分 tick 无意义 |

**Cons**：把「什么时候值得想」交给时钟，是 ADR-010 已经否过的偷懒。**否**。

### Option D：每轮都让 LLM 做任务级调度（ReAct 原教旨）
| 维度 | 评估 |
|---|---|
| 实现 | 低（把 goal 塞进 prompt） |
| 成本 | ❌ 每轮多一次推理；token 随目标数增长 |
| 可靠性 | ❌ 模型数不清步数/预算；会为了「继续」而编理由 |

**Cons**：与 ADR-004 的成本红线冲突；也是 AutoGPT 死循环的直接机制。**否**。

### Option E：目标栈放 `pet-core`（Rust 常驻）
| 维度 | 评估 |
|---|---|
| 延迟 | 微秒级 |
| 状态 | ❌ `pet-core` 是无状态内核（ADR-001），重启即失 |
| 决策 | ❌ 不做 LLM、不做调度 |

**Cons**：为了「快」把状态放进一个故意无状态的进程，是把架构约定当摆设。**否**。

### Option F：维持现状（只有当轮意图）
| 维度 | 评估 |
|---|---|
| 实现 | 0 |
| 长任务 | ❌ 跨轮即丢；无开放回路；无自主续跑 |

**Cons**：这正是本文要解决的问题。**否**。

## Trade-off Analysis

核心权衡是**「自主性 vs 可控性」**。全自主（B）体验上限最高，但失败模式是无限循环、烧钱、误伤；
全被动（F）最可控，但她永远只能「应答」，不能「把一件事做完」。

选 A 的理由是**把自主性拆成可审计的小步**：每个 goal 有 oracle、有预算、有风险等级、有终止条件；
每一步都能回答「这是哪个 goal 的哪个子任务」。这比「让她自由」更难写，但它是唯一能进评测的形态。

第二个权衡是**「规则 vs 模型」**。规则打分在 v1 会漏掉「她真的该主动做的事」；代价是自主性偏保守。
这是故意的：ADR-003 已经定过「先规则后学习」，目标选择的数据（什么目标被接受/被放弃）要攒够才配训 ranker。
缓解：v1 只开 `user` 与 `open_loop` 两类来源；`curiosity` 留开关、默认关。

第三个权衡是**30s 心跳的延迟**。用户看到的「她自己在做事」最多晚 30 秒启动；换来的是 0 LLM 空转与可预测的成本。
用户显式发起的任务不受影响（事件驱动，立即进现有循环）。

## Consequences

- ✅ 新增的全是宿主侧纯函数与一个小 JSON 状态机，可单测，不需要真机
- ✅ 无目标时 0 成本；有目标时 30s × <1ms，且不调 LLM
- ✅ 与 ADR-006 的计划对象、ADR-007 的熔断、ADR-010 的开放回路天然衔接
- ⚠️ **规则评分会显得笨**：v1 可能「该主动时不动」。先接受，用 `open_loop` 与用户显式请求兜住
- ⚠️ **持久化可能过期**：重启后 active→paused，必须重新观测 + 重新验证；不能盲目续跑
- ⚠️ **30s 延迟**：自主任务启动慢半分钟；用户主动发起不受影响
- ⚠️ **goal 与 plan 是两种对象**：goal 跨轮、plan 一次性；不要把 goal 直接塞进 plan，也不要把 plan 当技能存（ADR-012）
- ❌ 不做多 agent 并行、不做 DAG、不做常驻 daemon、不做「她给自己生成新目标」的开放循环
