# ADR-004：世界感知与推理成本 —— 只注入变化，小模型不进帧循环

**Status:** Accepted（2026-11-17，Phase 1 已落地）
**Date:** 2026-11-17
**Deciders:** 用户（成本红线拍板）· 主会话

## Context

要让「她对世界有整体感」，天然趋势是「感知越多越好」——但三条成本线同时压着：

1. **感知成本（本地）**：截图+OCR 全窗 4.87s，不可能常开；
2. **Token 成本**：每轮 prompt 已 ~8.8k，前缀缓存命中率 88–97% 是命脉；
3. **人的注意力**：主动开口是最贵的资源（被打断一次，信任掉一截）。

同时 §61.8 认定「情绪/意图路由值得小模型化」，而 LumenAct 的选择器实测 CPU **7.5–8.5ms** ——
既不算便宜（相对 1ms 的 Rust 调用），也远没到必须上 GPU 的程度。

## Decision

1. **采样分级**：1s 便宜源（前台/空闲/SMTC/剪贴板指纹）常开；UIA 只在窗口变化时读；
   截图/OCR/VLM 只在按需 + 有预算时跑（云端 VLM ≤6 次/小时；本地 Ollama 仅 `free_mb ≥ 6000`）。
2. **注入只写变化**：世界状态每轮取**一次**快照，只写与上一轮不同的字段，
   ≤100 tokens（硬上限 120），全都没变**完全不注入**；只进最后一条 user 的**易变尾巴**，
   system/tools/历史一字不动。
3. **小模型不进步循环**：>5ms 的推理（38M 选择器 8ms、任何 VLM）一律放**常驻服务**，
   渲染层只消费结果；帧循环里只允许纯 JS 采样（实测 0.0089ms/帧）。
4. **打扰预算独立于感知**：感知到的活动状态是「事实」，说不说话由 `speech-budget` 决定。

## Options Considered

### Option A：世界状态进 system（每轮更新一段）
| 维度 | 评估 |
|---|---|
| 实现 | 简单 |
| 前缀缓存 | ❌ 每轮打穿（8.8k prompt 全价） |
| Token | 每轮多几十～几百 |

**Cons**：直接违反缓存红线；实测同样内容放尾巴，命中率保持在 93% 上下。

### Option B：世界状态只放易变尾巴（选中）
| 维度 | 评估 |
|---|---|
| 实现 | 中（要做 diff + 预算裁剪） |
| 前缀缓存 | ✅ 不动前缀（system+tools 两轮 hash 一致，有断言） |
| Token | 每轮 0–48（实测） |

### Option C：后台 VLM 持续理解画面
| 维度 | 评估 |
|---|---|
| 实现 | 中 |
| 成本 | ❌ 本地显存被游戏抢、云端按次计费 |
| 收益 | 与「变化才看」相比边际很低 |

## Trade-off Analysis

「只写变化」的代价是**状态有状态**（要记上一轮注入了什么），
收益是「世界不变时零成本」—— 实测 3 轮里 1 轮完全没注入。
这条规则和缓存红线是同一条纪律：**任何「每轮都不同」的东西都不能进前缀**。

「小模型不进帧循环」的代价是跨进程调用（管道 1ms / HTTP 数 ms），
收益是渲染帧不被阻塞 —— 而 8ms 的模型放在 60fps 循环里等于每帧丢一半。

## Consequences

- ✅ 世界感知常开成本 3.8–4.2ms/秒（低功耗 122µs），世界行最大 48 tokens
- ✅ 缓存命中率 93.2% / 92.9%（两轮实测）
- ✅ 采样器坏了只影响一行字，不影响对话主链（stale → 少一个字段）
- ⚠️ **过期事实不能当证据**：媒体适配器停掉后 `playing` 会「新鲜」到 4×TTL（实测踩到，已修）
- ⚠️ **idle 毫秒不能进变化历史**（每秒都变，66 秒冲爆 200 条）
- 🔁 要复查：Phase 2（RSS/通知）必须**批量 + 去重 + 一天一次简报**，不许逐条调 LLM
