# ADR-014：成本与缓存治理 —— 不牺牲工具质量的前提下砍尾巴、降地板

**Status:** Accepted（2026-11-24，用户逐项拍板）
**Date:** 2026-11-24
**Deciders:** 用户 · 主会话 · 子代理 A/B/C

## Context

2026-11-24 的周配额耗尽（429 原文：weekly usage limit，16:30 重置）不是「限流」，
而是**成本结构**问题。审计与实测数字：

- 单请求 p50 14.7k：tools 6.3k（43%）+ history 4.8k（33%）+ system 3.8k（26%）；
- 每轮 4.8 次请求 → p50 一轮 ~70k；p90 单请求 64.5k、峰值 78k → p90 一轮 300k+；
- 缓存加权 67.2%，28% 请求 0%；重启后前 1–2 次 0%；
- 上一轮已做：p90 尾巴（工具回执 8k/24k、压缩 8k+4k 回差、硬裁 48/24k）、
  错误透出、llm-health 熔断、cache telemetry、后台预算拆分。
- 外部源码核对：OpenCode（缓存感知预计算/持有摘要、50KB/2000 行工具输出 + outputPath）、
  Pi（2000 行/50KB + offset、keepRecentTokens、prompt_cache_key）、
  ZCode（provider usage 基线 + willRetrigger/rapidRefill、summarySource session_memory、
  goal tokenBudget）、DSH（工具配对平衡切点、配额错误分类）、DeepSeek 官方（前缀缓存从 token 0、
  system→tools→messages、改早期内容整段 miss、命中约 1/10 价）。

## Decision

分三轨，按「质量零损失 → 可配置取舍 → 战略」推进：

### 轨道 1（质量零损失，先做）

1. **Provider usage 基线**：以真实 `prompt_tokens/cached_tokens/cache_hit/miss` 为基线，
   只估算「上次请求之后新增的消息」；压缩/硬裁阈值从「字数估算」改为真账。
2. **成本/配额账本**：每次请求记录 input/output/cache read/write/miss + label；
   doctor 显示今日/近 7 天 token、加权缓存、p50/p90；`cost.weekly_token_budget` 可选，
   默认 null 只统计，80% 告警（用户拍板：先统计+80% 告警，不拦截）。
3. **工具顺序稳定**：`getMergedToolsList` 按 name 排序，跨插件热重载/重启的前缀一致；
   加断言。
4. **缓存感知压缩**：达到触发线时先生成摘要但**持有不替换**；到更高水位（约 12–16k）
   或硬上限前才应用；tail 太长/摘要过期则重做。避免每次压缩都打穿前缀缓存。
5. **压缩遥测 + rapid-refill 闸**：记录 pre/post/truePost、trigger/reason、
   willRetriggerNextTurn、连续快速回填；防止「压完立刻涨回来」抖动。
6. **工具回执 12k/32k + 可续读**：单条 12k、单轮 32k；超出时给 `offset`/`limit`/`next`
   或全文 artifact 路径（`data/tool-artifacts/`），模型可续读；artifact 有上限/清理，
   不编进记忆索引。工具语义与独立性不变。

### 轨道 2（有取舍，已获用户授权）

7. **会话级动态工具子集**：`toolFilter.enabled=true` 时按当前模式选一次、**整个会话保持**
   （不是每轮变），核心工具永在、minKeep 保底；模式切换才换。**不合并工具**（用户拍板工具要独立）。
8. **画像 20→10 条/字段 + 按需全文**：system 里的画像降到 10/字段，完整画像继续由
   `profile view` 工具提供；省约 0.6–0.7k/请求。
9. **看屏 VLM 预算 220→90 次/小时**：静默期仍 0；画面描述变粗，但不再无上限烧视觉调用。
10. **本地记忆模型**：`llama.cpp server` + **MemOperator-4B Q4_K_M**
    （MemTensor，Qwen3-4B 底座，32K，Apache-2.0，GGUF 2.6GB，来源 `mradermacher/MemOperator-4B-GGUF`）。
    - 本机已有 `D:/llm/llama-cpp-turboquant/llama-server.exe` b8671（CUDA，支持 `-ctk/-ctv/-fa/--jinja/-nkvo`）；
    - 32K 上下文、`-ctk q8_0 -ctv q8_0`、全 GPU（权重 2.33GiB + KV 2.39GiB ≈ 5.3GiB，4060 8GB 可跑）；
      8B + 32K + KV q8 需 7.67GiB，放不下；9B/128K 本机不现实；
    - 摘要（片段卡/画像/日记）与 MemOS `/add` 抽取走本地；**反思仍走云端**（质量敏感，4 次/天）；
    - 本地不可用时跳过并留日志，**不静默回退云端**（避免再次意外烧配额）；
    - **本地任务的闸独立于云端配额**：云端 429 暂停不应拦住本地摘要/抽取；用 `canRunLocal`
      （用户开关 + 本地 `/health`），反思/判官等云端任务继续用 `canRun`（用户开关 + llm-health）。

### 轨道 3（战略，另立 ADR，不在本轮）

- Code actions / 工具批处理（smolagents 式，理论 -30–50% 请求数）；
- mid-turn 压缩 / session-memory 压缩；
- 配额耗尽自动切 provider（wb/Ollama）；
- 全量 `/responses` + previous_response_id 迁移。

## Options Considered

### Option A：只做 A 类（缓存/账本/续读）
| 维度 | 评估 |
|---|---|
| 质量 | ✅ 零损失 |
| 成本 | 缓存命中提升 + 压缩抖动下降；p50 地板不动 |
| 风险 | 低 |

### Option B：全做（本轮选择）
| 维度 | 评估 |
|---|---|
| 质量 | 动态工具/画像/看屏有可感知取舍；工具独立性不变 |
| 成本 | p50 省约 2.5–3.5k/请求；后台摘要云端归零；视觉调用降 60% |
| 风险 | 中；全部有开关/可回滚 |

### Option C：激进（合并工具 + 4k 压缩 + 本地视觉）
| 维度 | 评估 |
|---|---|
| 质量 | ❌ 违反用户「工具要独立」拍板、压缩丢现场、本地视觉细字差 |
| 成本 | 最低 |
| 结论 | 不采用 |

## Trade-off Analysis

- **为什么先缓存/账本**：DeepSeek 命中约 1/10 价，命中率 +5–10% 等于有效 prompt 成本
  -10–20%，且不改任何行为；比砍功能安全。
- **为什么 4B 本地**：8B + 32K + KV q8 需 7.67GiB > 8GB 可用；4B 同 KV 形状（36 层×8 KV heads×128）
  但权重只 2.33GiB，32K q8 合计 5.3GiB，速度 60–80 t/s；MemOperator-4B 的 LOCOMO 0.7714
  超过 GPT-4o-mini（0.7405），是「记忆专用 + 能跑」的交点。128K 即使 q4 KV 也 10.7GiB，
  本机不现实；32K 对记忆总结够用。
- **为什么反思留云端**：一天 4 次、质量敏感；本地 4B 的反思质量未校准，先不冒险。
- **为什么工具不合并**：用户 2026-11-14 拍板「工具要专门独立才有作用」；用会话级子集降 token，
  不用合并降数量。

## Consequences

- ✅ p90 尾巴已有上限；p50 地板通过动态子集/画像减半再降 2.5–3.5k/请求；
- ✅ 缓存命中可测、可预警；压缩不再每次打穿前缀；
- ✅ 工具截断从「丢内容」变成「可续读」，质量风险下降；
- ✅ 后台摘要/MemOS 抽取不再消耗云端配额；反思仍云端、质量不变；
- ⚠️ 动态工具子集可能让模型暂时不知道某工具；有核心保底 + 模式稳定；
- ⚠️ 画像只放 10/字段，细节要靠 `profile` 工具补；
- ⚠️ 看屏描述变粗；本地摘要质量待真实语料 A/B；本地模型不在时后台跳过；
- 🔁 要复查：16:30 后 2–3 天 p50/p90、缓存加权、压缩次数、本地模型 t/s、记忆兑现 used。

## Non-goals

- 不合并工具；不用本地视觉分档；不做启动预热 / 4096 填充；不追 128K；
- 不做全量 Code Agent 重写；不跑 30B 记忆模型；不自动切 provider；
- 不改本地 TTS、检索排序、人格/system 稳定性、记忆原文写入。
