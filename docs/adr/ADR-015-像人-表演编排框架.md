## 1. Context：现在到底什么样（全部实测，不是推测）

### 1.1 素材三层

| 层 | 数量 | 时长 | 通道 | 有声音 | 谁能触发 |
|---|---|---|---|---|---|
| 短场景 `SCENES` | 12 段 | 3–4s | 情绪 + 动作词典 + 换装 + 一句 `hint` + sfx | 有（台词/音效） | 手点（8103 `/perform`），优先级最高 |
| 长表演 v2 `CHOREO_DATA` | 15 段 / 461 轨 / 2531 点 | 18.8–37.7s | Live2D 参数级轨道（角度/身体/表情/手势） | **无** | 自动三通道（说话起手 / 说完强情绪 / 空闲 2.5min）+ 手点 |
| 面部片段 LumenAct | 97 段 | **1.1–52s**（中位 3.5s，14 段 >10s） | 5–16 条 FACS 通道 | 无 | 规则导演（能量/冷却/情境门）+ 空闲通道 |

> 修正一个流传已久的说法：97 段片段不是「2–4 秒」，最长 52 秒。这条改变问题定义（见 §1.3）。

### 1.2 现有选择与仲裁

- 决策：`choreo-auto.mjs`（强度≥0.35、全局 3min、同段 6min、会话 12 段）与 `facs-clip-director.mjs`（energy≥150、90s 冷却、10min≤4 次、说话/离开不演）。
- 仲裁：`performance-arbiter.mjs`，`scenes/manual 5 > clip 3 > v2 2 > micro 1`，同帧单一 owner；**只有 manual 可 preempt**，被顶掉的层直接 `stop()`（无收势）。
- 参数写入：`choreo-performer.mjs` 直接写参数轨（说话时跳过 `ParamMouthOpenY/ParamMouthForm`）；`perf/mixer.mjs` 有 5 层（idle/emotion/speech/reaction/manual，additive/max/set），但长戏与片段在仲裁层就互斥，**叠不起来**。
- 调参：`js/core/choreo-tune.js` 用「演完 90s 内用户是否输入」当被接率，倍率夹 0.5–2，样本 ≥20 才动。

### 1.4 代码审计补充（`docs/research/表演管线-代码审计-2026-11-25.md`）

六条会改变实施顺序的硬事实：

1. **v2 不读在场**：三个自动通道只传 `emotion/strength/now`（`petbody-entry.mjs:1423,1452,1501`），away 时照演 20–38 秒；`away` 只拦便宜的面部片段。
2. **空闲判据是「她没说话」**（`petbody-entry.mjs:1443`），不是「用户不在」；纯文字聊天也不重置情绪 idle（`emotion-engine.mjs:419-443` vs `455-480`）。
3. **clip 库一半不可达**：`minEnergy=150` 下 47/97 段被废；`playful` 只剩 1 段；top4 中性长片（33.6/27.8/52/29.5s）吃掉 866 次播放 ≈ 8.2 小时，被接率 0–5.8%。
4. **v2 内容空心**：编译器丢掉 122 条手臂/手指轨、34 条表情轨（`tools/compile-performances.py:85-91`），06/07/08 段 18.8 秒只剩 7/6/8 轨。
5. **没有同步点/收势/排队**：`steps` 数据在但运行时只用条数；抢占一帧硬切、手势资产不回收（会留在手上）；每段从零姿势起（`performanceEnvelope` inW 从 0 开始）。
6. **v2 是「所有权黑洞」**：它绕过 `mixer` 直接写 Cubism 参数，而 `checkWriteSet` 只查 perf、冲突探针把 `choreo` 归为 compose（`param-ownership-probe.mjs:54-56`）、`ParamMouthForm`/`LeanInput` 连所有权表都没进、exp3 的 `脸红/流泪/流冷汗` 不受 pin 约束。**在修好这些之前，任何叠层/节目单都会引入静默双写，而仪表仍是绿的。**

另：`SCENES` 的 `hint` 是死数据（`perform()` 不发），字幕靠两份硬编码 6 段表；`performance-log` 的「被接」把「打断」和「演完才说话」混在一起（`lp.at` 是开始时间）。

结论：**「不像人」的主因不是内容少，而是密度与时机**——长段当背景动画连续放，演出退化成「会动的壁纸」，不构成事件，用户自然不会回应。这与学术结论一致（§2 原则 3/4）。

### 1.4 现有信号（导演层可用的输入）

- 世界感知：前台进程/标题、系统空闲秒、五态活动机（working/video/game/away…）+ why/conf。
- 对话现场：`topic/lastSpeaker/lastUserAt/lastCompanionAt/mood`（各自 TTL）。
- 看屏：`organ` 摘要、一起看事件、静默期。
- 表演日志：play/skip/user_input_after 全量。

## 2. 第一性原理（按技能要求输出）

### 2.1 claimed_constraints（被当作固定的限制）

| 约束 | 分类 | 处理 |
|---|---|---|
| 实时回路不能调 LLM（延迟/成本/不可审计） | **实测事实** | 保留。LLM 只进慢回路（原则 5） |
| 8GB 显存与她本体共享 | **实测事实** | 保留。不引入新常驻模型 |
| 只有 authored 曲线，没有全身生成数据 | **实测事实**（ADR-003 已定） | 保留。生成式后置 |
| 「长表演必须 20–38 秒」 | **惯例**（素材如此，不是需求） | 丢弃：可以只演 8 秒的片段，也可以串多个短段 |
| 「自动演出越多越像活人」 | **惯例/直觉** | 丢弃：实测 183 次/天、被接率 2.5–4%，密度与像人度负相关 |
| 「连戏 = 把长段再拉长」 | **类比** | 丢弃：连戏应是「事件化编排」，不是延长单段 |
| 「片段与长戏不能叠」 | **实现现状**（非物理） | 重新谈判：mixer 有 5 层，可按通道叠（原则 1/2） |
| 卡通皮不能配细表情 | **已被文献否证** | 丢弃：一致性 > 更真（MacDorman 2015） |

### 2.2 primitives（可独立支撑的事实）

1. 「像人」的可观测维度只有五个：**何时**（时机）、**做什么**（内容）、**做多久**（时长/收势）、**说什么**（声音）、**被打断怎么办**（交互）。现有系统只覆盖了「做什么/做多久」。
2. 人对**周期性**极敏感；固定冷却 + 均匀随机 = 可识别机械感（Streck & Wolbers 2018）。
3. 表演要成为「事件」才有社交意义：有开始、有结束、有可回应的对象；连续背景动画不产生回应（实测被接率 1.6–4.4%）。
4. 参数写入必须单点仲裁（ADR-002/现有 arbiter 已验证），但**仲裁粒度应是通道**，不是整段。
5. 8GB / 5ms 帧预算下，任何新层的计算都必须是 O(1) 查表 + 纯函数。

### 2.3 discarded_assumptions（丢弃的惯例）

- 「长 = 像人」：丢弃（数据反证）。
- 「多演 = 活泼」：丢弃（被接率反证）。
- 「必须实现完整 BML 解析器」：丢弃，只借调度语义（同步点/抢占/收势/change-shape）。
- 「换更写实的动作/口型」：丢弃（恐怖谷文献：一致性优先）。

### 2.4 rebuild（只用基本事实重建）

最小闭环 = **一个事件化的演出调度器**：

```
presence + 对话现场 + 情绪 + 预算
        ↓（导演：此刻该不该演、演多重、最多多久）
   演出请求（带同步点、可打断窗口、音轨、目标时长）
        ↓（调度器：排队/抢占/收势/按通道过渡）
   执行（v2 轨 / clip 轨 / 节目单串接）
        ↓（收尾：回落到 ambient 低幅度待机）
   遥测（planned/actual/interrupt/skip + 被接率）
```

### 2.5 kill_test（最便宜的证伪）

- 同一批「用户在场且刚交互」的 8 个场景（n=8，脚本化对话），对比改动前后：**被接率**与**不合时宜率**（演出发生在 away/game 的比例）。若被接率不升、或不合时宜率不降 → 设计失败。
- 更便宜的前置证伪：把密度从 183/天 压到 ≤40/天（纯配置+预算），看主观观感是否已改善；若压密度后仍像壁纸，再上节目单。

## 3. Decision

### 3.0 组件零：护栏（必须先做，否则后面全是假绿）

1. **写入集入册**：把 v2 的 `choreo/choreoOverride` 写入参数纳入 `checkWriteSet`；`ParamMouthForm`、`LeanInput` 补进 `EXTERNALLY_OWNED_PARAMS`；`COMPOSING_LAYERS` 移除 `choreo`（它是写者，不是合成器）；exp3 的 `key7/key2/key13` 纳入 pin 过滤。
2. **日志语义**：`performance-log` 区分 `during`（打断）与 `afterEnd`（被吸引），并记 `endedBy`；被接率只统计 `afterEnd`（导演用另一个指标「打断率」）。
3. **在场判据**：v2 与 clip 统一从 `globalThis.__worldSenseState().activity` 取 `working/gaming/watching/meeting/idle/away`（渲染层零 IPC 可读），回退 `__userActivity` 且做 30s freshness 检查；`away` 时 v2 **不许启动**。
4. **内容快胜（不改素材）**：clip 候选加「时长 ≤ intensity 预算」（低强度只允许 ≤8s）、按情绪稀缺度放宽 `minEnergy`（`playful` 可用段从 1 提到 ≥5）、每段每日播放上限（防 top4 垄断）。
5. **失败必须发声**：护栏命中时 `perf.skip.reason` 必须带具体原因；`paramOwnershipStats.conflictFrames>0` 时 doctor 转黄。

### 3.1 组件一：调度器（Scheduler）——在现有 arbiter 上升级，不重写

- 新增 `pet-runtime/desktop/perf/perf-scheduler.mjs`（纯模块，可单测），对外 API：
  ```js
  request({
    owner: 'scenes'|'manual'|'clip'|'v2'|'program'|'ambient',
    key, priority,            // 缺省按 owner 优先级
    kind: 'atomic'|'segmented', // atomic=不可打断（3–4s 短场景）；segmented=按 sync 点可打断
    sync: { prep, stroke, relax[], end }, // 来自离线标注，见 3.2
    channels: ['face','head','body','gaze'] // 允许写的通道（通道级仲裁）
    audio: { lines?, sfx? },  // 可选
    maxMs,                    // 目标时长上限（导演给的预算）
    ttlMs
  })
  ```
- **抢占规则**：
  - `manual` 可立即抢占，但也要 0.15s 过渡（不做硬切）；
  - 其它 owner 只在当前行为的 `relax` 点抢占；无 relax 点则排队等 `end`；
  - 抢占时对旧 owner 执行**收势**（按通道 0.1–0.2s 眼/头、0.3–0.5s 身体），期间新 owner 处于 `pending`。
- **约束而非时间表**（BML realizer 的可移植思想，调研结论 A）：节目单只声明相对约束（「B 在 A 的 relax 后 0.3s」），调度器求可行解；改戏只重解约束，不重排死时间。新行为先 **reserve**（对应 Cubism `reserveMotion`/`setReservePriority`）再等 relax，避免「宣布了却没位置」。
- **热切换**：借 AIRI `Driver.replace(generator)` 的语义（MIT，不释放所有权直接换生成器）——我们的版本是 `replaceCurrent(next)`，在收势结束后切换，不经过 stop/start 的空档。
- **通道级仲裁**：`manual/scenes` 独占 face/head/body；`clip` 只申请 face（眉/眼/嘴形）；`v2` 申请 head/body + 允许 clip 同时申请 face 的 max 通道。默认策略仍保守（互斥），新策略由 `performance.channel_overlay.enabled` 控制，默认 **false**（先上调度，再开叠层）。
- **兼容**：保留 `begin/end/availableFor` 旧 API 作为 thin wrapper，所有现有调用点不改也能跑；新 API 逐步替换（接入点：`petbody-entry.mjs:168,612,1928`）。
- **前提**：`choreo-performer` 现在只有 `stop()`（一帧硬切），必须补 `fadeOut(ms)` 与「补发手势 exit」；否则收势无从谈起。v2 不在 `mixer` 里（直接写 Cubism 参数），调度器只管「谁在写、何时换」，不改变写入路径。

### 3.2 组件二：同步点标注（离线）

- 新脚本 `pet-runtime/tools/annotate-performances.mjs`：
  - 对 15 段 v2：按轨道能量包络 + 段内步骤（steps 已有 pose/expression/gesture 起点）标注 `prep/stroke/relax/end`，保证**每 3–5 秒至少一个 relax**；不足则插入微 relax（不改轨道，只标时间点）。
  - 对 97 段 clip：按 19 通道能量包络标注。
  - 产物：`pet-runtime/data/perf-sync.json`（一次性生成，随素材版本哈希；缺文件时调度器退化为「整段 atomic」，不报错）。
- 纯离线，不增加运行时计算。

### 3.3 组件三：导演（Director）

`pet-runtime/desktop/perf/director.mjs`（纯函数）：

- 输入：`presence`（`__worldSenseState().activity` 六态 + `__userActivity` 回退 + 30s freshness + `conversationScene` 新鲜度）、`emotion{key,strength}`、`sessionStats`（最近 10 次 `afterEnd` 被接率与 `during` 打断率）、`now`、`lastPerfAt`。
- 输出：`{ allow, intensity 0..1, maxMs, minGapMs, maxPer10Min, allowedKinds[], reason }`。
- **上线方式（审计建议）**：先 **dry-run 24h**——只写 `perf.request {allowed:false, reason}` 日志、不拦截任何表演；拿到「本来会被拦掉多少、拦得对不对」的真实分布，再开闸。这条把「拍脑袋调参」变成有数据。
- **接线点**：T1 `petbody-entry.mjs:1406` 前、T2 `:1501` 前、T3 `:1452` 前、clip `:661-675`/`:1213`/`:1263`；`allow=false` 时**不调用 `consider`**（避免白吃冷却）。
- **强度曲线**：会话开始 5 分钟 = 低（intensity 0.3，只允许短场景/微动作）；有连续 3 轮对话 = 中（0.6）；用户主动点她/长对话 = 高（1.0，允许 v2/节目单）。
- **预算**：正常日 ≤40 次播放（含微动作）、长段 ≤12 次/天；`maxPer10Min` 从 4 降到 2；away/game/video 时 `allow=false`（保留极轻 ambient）。
- **被接率闭环**：最近 10 次被接率 <15% → intensity 乘 0.7 且 `maxPer10Min-1`；>40% → 允许 +1。贝叶斯平滑（复用 `choreo-tune` 的公式，不新造）。
- 与 `choreo-tune` 分工：tune 管「段级偏好」（慢，日志周级），director 管「此刻该不该演」（快，会话级）。两者串联，互不替代。

### 3.4 组件四：待机层（Ambient）

**P1 先做「低技术、立刻不僵」的三件套**（开源调研已验证公式与许可）：
- **加权待机池**（ChatdollKit，Apache-2.0，抄公式）：`P(i)=weight_i/Σweight_j`，常用 3 / 少见 1；「被接率」直接映射成 weight（样本≥20 才动，复用现有门槛）。
- **非固定间隔**（AI-Vtuber，GPL → **只抄公式不抄代码**）：`next_delay ~ U(90s, 300s)`，每次重新抽样；同一状态不连续复用。
- **程序化呼吸**（Amica 常量）：`base + amp·π·sin(t)`，相位一致、幅度分级（脊柱 0.04 > 颈 0.02 > 腿 0.01），周期 4–6s。

**本层状态机**（`ambient.mjs`）：6 状态（quiet/observe/bored/sleepy/playful/settle）+ 对数正态停留（μ 按状态、σ=0.6，钳 [20s,8min]）+ 效用 margin（`score_i = U_i + ε_i`，`ε~U(0,0.05–0.15)`，再乘 `0.7^最近次数` 的惯性惩罚）。幅度上限 = 表演的 30%，且必须 > 脏帧阈值 0.0015（否则渲染器会跳过重算）。

**P2 可选升级（AR-HMM）**：AIRI（MIT）的 `stateCount 3–5 + order 2–4` AR-HMM，用我们 15 段参数级长表演当训练集；`meanDwellSeconds` 作为停留先验、`noiseScale` 调活泼/呆滞。纯 CPU、8GB 无压力，但属「生成式待机」，等 P1 数据证明需要再上。

### 3.5 组件五：节目单（Program）——连戏

- 数据：`pet-runtime/data/programs/*.json`
  ```json
  { "id": "curious-then-proud", "title": "疑惑→得意", "beats": [
      { "seg": "01-curiosity", "at": 0, "maxMs": 12000, "line": "诶……这是什么东西？" },
      { "seg": "03-pride", "at": "after", "transitionMs": 400, "line": "哼哼，我早就知道了。" }
  ]}
  ```
- 运行器 `program-runner.mjs`：按 `relax` 点串接；段间过渡按通道；用户说话 → 在下一个 relax 点停止（或按导演降级为只听不演）。
- **台词对齐直接抄 Open-LLM-VTuber 的句子流水线**（MIT，调研已验证）：`pysbd` 中文分句 + 逗号级流式切分 + 缩写白名单；`sequence_counter` 保证「并行合成、串行交付」；每个音频 payload 挂 `display_text + actions`，句首应用动作/字幕。**句边界天然是 sync point**，不另建时间表。
- 可选补充：ChatdollKit 的内联标签（`[face:]/[anim:]/[pause:1.5]`，Apache-2.0）只在「LLM 写台词」时启用；我们自己的节目单 JSON 不需要。
- 将来若要让长戏「张嘴跟语音」，用 Rhubarb Lip Sync（MIT，产出数据归用户）离线生成 viseme 轨，与 FACS 通道**相加**而非覆盖。
- 节目单**不是更长**：单条 45–90 秒，最多 3 段；默认每天最多 2 条，只在 intensity≥0.8 时允许。

### 3.6 组件六：慢回路编剧（默认关）

- 任务：每天/每 3 小时一次，用云端 LLM 产出「今日基调 + 2 条节目单草案 + 3 条 beat 触发规则」。
- 产物必须过 schema 校验 + 白名单（段 key 必须存在）；写入 `programs/draft-*.json`。
- 开关 `performance.writer.enabled`，默认 **false**；开启也不进实时回路。

## 6. 风险与护栏

1. **参数所有权冲突**（最大风险，审计已定性为「所有权黑洞」）：v2 绕过 mixer 直接写 Cubism 参数，而断言只查 perf、冲突探针把 `choreo` 归 compose、`ParamMouthForm`/`LeanInput` 未入表、exp3 不受 pin 约束。**P0 必须先修这四条**，否则 `conflictFrames=0` 是假绿；叠层（P4）之前还要单独跑一次全量参数对拍（30 轮 × 15 段）。
2. **帧预算**：调度器/导演/ambient 全部纯函数 + 查表，每帧只做一次决策（不在 rAF 内跑循环）。**验收指标以实测为准**（审计：`updateView` 单帧 10.7ms，其中 `_model.update()` 6.29ms；代码里没有 5ms 预算）→ 改判 `_updateCostMs` p95 ≤12ms，新增层自身开销 p95 ≤0.5ms。另：`choreoTuning` 每 10 分钟在 rAF 内同步 `readFileSync` 723KB（`choreo-tune.js:458`），会造成 5–20ms 卡顿——P1 必须把它移出帧循环（增量读尾部或异步缓存）。
3. **热重载**：新模块挂在 petbody bundle 内，dispose 时释放 claim（沿用现有 `dispose` 兜底）。
4. **测试污染**：所有新单测必须设 `PET_DATA_ROOT`；不得写真实 `performance-log.jsonl`。
5. **UI 契约漂移**：能力页数字不再写死；新增契约测试（键存在 + note 不含魔数 + 开关走白名单）。
6. **许可**：新台词/音效必须进许可台账；不引入新素材时只用现有 sfx。

## 12. P4 决定（2026-11-25）：通道叠层与慢回路编剧**本版不接线**

**状态：Deferred（配置键保留，缺省 false；不建假开关）**

### 12.1 通道叠层（clip + v2 同时写）
- 现状：v2 绕过 mixer 直接写 Cubism 参数；P0 已把它的写入集纳入断言，但 arbiter 仍是**单 owner** 语义，且 v2 的轨道同时包含脸（37 条 mouth、20+ 条 eye）与身体，没有「v2 只写身体」的现成掩码。
- 要安全叠层，至少还要：① 给 v2 的每段做面/身通道掩码（或运行时按通道过滤）；② arbiter 支持**通道级多 claim**；③ 30 轮 × 15 段参数对拍 + `conflictFrames=0`；④ 帧预算复测（当前 `updateView` 已 10.7ms）。
- 判断：收益是「长戏期间脸更细」，风险是把 P0 刚补上的所有权护栏再打穿。**本版不做**，留到有真机主观证据（长戏脸太僵）时再评估。

### 12.2 慢回路编剧（LLM 生成节目单）
- 收益不在实时观感，而在「省人工写段子」；我们目前只有 2 条手写节目单，还没到需要批量生产的规模。
- 且编剧产物需要 schema、段 key 白名单、许可台账与人工复核，**默认关也仍需维护**。
- 判断：**本版不接线**；等节目单数量 >10 或用户明确要「每天新段子」再做。

### 12.3 保留项
- `performance.channel_overlay.enabled=false`、`performance.writer.enabled=false` 两个键保留在配置里（能力页可见、标「未接线」），便于将来接线时不改契约。
- 若未来接线，前置条件写进对应批次：叠层必须先过 30 轮参数对拍；编剧必须先有 schema 校验与人工复核流。
