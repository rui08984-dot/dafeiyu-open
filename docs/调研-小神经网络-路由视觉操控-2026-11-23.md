# 调研：几 MB～几十 MB 小神经网络（路由 / 工具选择 / 纯视觉游戏 / GUI 操控 / 拟人化）

> 2026-11-23 · 只读调研，未改源码。口径：论文与仓库许可**逐条抓原文核实**；体积/延迟凡未亲测均标「估算」或「未核实」。
> 与既有结论对齐：`docs/实测-响应延迟与意图路由-2026-11-09.md`、`docs/adr/ADR-004`、`ADR-008`、`docs/设计-纯视觉游戏操作框架-2026-11-14.md`、`progress.md §121.6`。

## 一、结论先行

1. **路由不该再为「延迟」做**。自家实测：省 52 个工具 schema 只赢 230ms，而 TTFT 抖动 ±206ms；正则 2µs/95%/0 危险误判。小模型只剩三个正当理由：省 token（按量计费）、离线可用、隐私不出本机。且只做**影子/建议**，不做硬闸。
2. **工具选择是这五类里唯一「投入小、收益可计价」的**：52 工具 ≈ 4.5k tokens/轮，嵌入检索到 top-8 可省 ~3.5k。但 ToolRet 证明通用 IR 模型在工具检索上会显著掉点——必须先量我们自己的 recall@8，再谈上线。
3. **纯视觉的正确答案不是「更大的模型」**。开源界能跑的全是高频 CV 反射环；真正的空白是**闪避的前摇识别**（8–16 帧时序，<1M 参数），这也是项目自己已经点出的差异化点。L1 感知已吃 8–30ms、注入 28ms，闪避模型必须 <2ms 且只吃 ROI 小图，否则进不了 28–39ms 的闭环。
4. **GUI 兜底不要 VLM**。OmniParser 权重（CC-BY-4.0 + 0.23B 描述器）已被本项目否决；正确替代是 Apache-2.0 的小检测器 + 现有 RapidOCR/UIA 融合，补「UIA 空壳 + 纯图标按钮」这一个洞。
5. **三条许可红线比性能更致命**：YOLOE 的 LICENSE 原文是 **AGPL-3.0**，Ultralytics 的 YOLO 系（计划中的 YOLO26 学生同门）按惯例也是 AGPL（该档未逐字核）；IRIS 是 **GPL-3.0**；OpenFace/openSMILE 是**非商用/研究许可**。闭源分发前必须先处理。

## 三、最值得先试点的 5 个

**1) 闪避时序模型（TCN/GRU，<1M）**——唯一「别人没做、我们有帧源」的点。最小验证：录 200 段 boss 前摇，切 8/16 帧窗口，离线比 AUC；达标线 AUC≥0.9 且端到端 <10ms。收益：差异化能力；风险：标注贵、帧同步错位会让 AUC 虚高。

**2) 工具 RAG（bge-small-zh 24M + 规则重排）**——唯一能把 token 账单打下来的。最小验证：影子模式跑 3 天真实请求，量 recall@8 与「全量 schema 下模型本会选的工具」是否一致。收益：省 ~3.5k tokens/轮；风险：长尾工具漏召 = 能力凭空消失，必须保留全量兜底开关。

**3) fastText 影子分类器（MIT，1–5MB）**——用来替代 `qwen3-0.6b` 的常驻意图（省 ~0.5GB 显存），而不是加延迟。最小验证：把现有 22 例正则样本扩到 300 条日志，5 折交叉，和正则逐类比 P/R。收益：零显存、离线；风险：中文短句靠 char n-gram，标点/语气词会干扰。

**4) GUI 图标检测（YOLOX-Nano 或 NanoDet-Plus，Apache-2.0）**——补 C 档「UIA 空壳 + 纯图标」。最小验证：用 UIA 的 `name` 自动标注 500 张截图，训一晚，在 50 个真实窗口上量「图标命中率 / 误检率」。收益：盲点可用；风险：DPI 与主题换肤导致域偏移，需按 profile 缓存。

**5) 拟人化：Utility AI + 检索式记忆（无 NN）+ 人设打分（复用嵌入）**——最便宜的一档。最小验证：把「说不说话/演哪段/要不要凑近」写成 6–10 条 utility 曲线，A/B 一周；人设打分用现成嵌入算余弦，阈值从历史对话标定。收益：行为更像人且可解释；风险：规则膨胀，需要一张可读的表而不是代码。

## 四、明确不建议

- **任何 1B+ 模型**：TinyAgent-1.1B（已核）、Hammer（>1B）、ShowUI-2B（已核）、UGround/OS-Atlas（≥2B/≥4B，档位未逐字核）、Qwen3-VL-8B。理由：游戏时显存只剩 0–2.1GB，且 CPU 上不满足交互延迟。
- **OmniParser 权重**：LICENSE 原文是 CC-BY-4.0（已核），与本仓库 README 的口径不一致（项目此前记录），且叠加 0.23B 描述器；只借算法不落地权重。
- **YOLOE-11s 与「YOLO26n 学生」**：YOLOE LICENSE 原文为 AGPL-3.0（已核）；Ultralytics 的 YOLO 系按同一策略授权（YOLO26 未逐字核）。若走「零样本当老师→小模型当学生」，学生会继承 AGPL；要闭源分发就换 Apache-2.0 的 YOLOX/NanoDet/RTMDet 系。YOLOE 只放在离线标注工具链里，产物与代码都不随产品分发。
- **IRIS（GPL-3.0）**：世界模型研究很漂亮，但许可与闭源产品冲突；同位置用 MIT 的 DIAMOND 做离线实验即可。
- **OpenFace / openSMILE**：一个「仅学术非商用」，一个「研究许可、商用需购授权」。面部 blendshape 用 Apache-2.0 的 MediaPipe；韵律特征用 librosa 自算 eGeMAPS 近似。
- **RouteLLM / RouterBench / IntentGPT / ToolkenGPT**：都预设「有一个强 LLM 和一个弱 LLM」或「有一个大模型在环」，我们的架构里这个前提不存在。
- **bge-reranker-base（278M/1.1GB）**：许可没问题，但体积与延迟都越界；52 工具场景用交叉编码器属于杀鸡用牛刀。
