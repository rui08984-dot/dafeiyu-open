# 设计：我们自己的操控层提升（2026-11-21 · 独立于 ZCode，服务整个皮套/项目）

> 起因：加载浏览器扩展任务里，我们的操控层（pet-core + act/see）与 ZCode CUA 各走了一遍。
> 实测问题归档在 `docs/审计-电脑操控两套链路实测-2026-11-21.md`。
> 本文回答：**我们自己的操控层怎么补强**。前提：**不依赖 ZCode**（它是外部插件，且对 Chromium independent surface 禁物理输入）。
> 边界不变：不新增进程/端口；`pet-core` 仍是无状态底座；对外工具面不扩张（能力补在现有动作内）。

## 1. 现状（已有，别丢）

| 能力 | 位置 | 说明 |
|---|---|---|
| 三层注入 | `dispatch` + `game-control.js` + `pet-core` | UIA 直调（不动鼠标）→ SendInput（后还原光标）→ overlay 虚拟光标 |
| 36 原语 | `game-control.js` | click/type/key/hold/scroll/drag/paste/set_value/get_value/select_text/perform/read… |
| 语义动作层 | pet-core `uia_action` | 按控件名/角色找元素并操作 |
| 回执契约 | `verify-contract.js` | `action_sent` / `effect` / `suspected_noop` / `retrySafe` |
| 前台校验 | `act` L3 | 不前台就拒发，`vetoCode 1001`，`action_sent:false` |
| 串行锁 | `game-control.js` | 动作不交错（按下/抬起成对） |
| DPI | pet-core | 物理坐标；PowerShell 侧需 `SetProcessDPIAware` |

## 2. 实测暴露的问题（本轮）

| # | 问题 | 影响 | 证据 |
|---|---|---|---|
| 1 | 坐标点击被拒后**不自动切前台** | 调用方要两步（focus→click），模型容易漏 | `act click` → `not_sent` + 1001 |
| 2 | 前台校验按**窗口标题**比对 | 同一应用的主窗+模态对话框互相视为「对手」→ 误拒 | focus 到「选择扩展目录。」后点主窗控件被拒 |
| 3 | 元素动作只试 `InvokePattern` | 「开发人员模式」这类不支持 Invoke 的按钮直接失败 | PowerShell 侧 `不支持的模式`（同族逻辑） |
| 4 | `act` 没有 `snapshot` | 排查界面要多一次 `see tree` 往返 | `act action=snapshot` 被枚举拒绝 |
| 5 | `see tree` 把对话框按钮标成 `pane` | 按类型的自动化会选错 | 「选择文件夹」→ `pane` |
| 6 | 无「等界面稳定」 | 动作后立刻读树可能读到旧状态 | 对话框弹出时序 |

## 3. 提升方案

### P0（本轮就做，直接解决实测卡点）

1. **自动 focus 重试**：`act` 的 L3 坐标点击遇到 `vetoCode=1001` 时，**自动**按同一 pid 找任一可见窗口 focus 一次，再重发一次动作（只重试 1 次，防止循环）。回执里记录 `autoFocus:true` 与两次的证据。
2. **前台校验按 pid**：目标窗口 pid === `GetForegroundWindow` 的 pid（或目标属于前台窗口的 owned popup）即视为前台。模态对话框与主窗不再互斥。
3. **元素动作三级回落**：对于元素点击，按 `Invoke → Toggle/SelectionItem → 坐标` 顺序尝试：
   - 有 `AXPress`/Invoke → 直调；
   - 是 Toggle/Radio/Checkbox → `TogglePattern` 或 `SelectionItemPattern.Select()`；
   - 都没有 → 用 UIA `BoundingRectangle`（物理）交给 pet-core 的坐标点击（它已 DPI-aware），但仍走前台校验。
4. **`act` 增加 `snapshot`**：复用 `see tree` 的扫描函数，返回与 `see` 同构的元素清单（action 枚举加 `snapshot`）。

### P1（下一轮）

5. **对话框控件类型补全**：对 `#32770` 窗口，把 `pane` 且可点击的节点按「有 Invoke/Press 动作」重新归类为 `button`；`editable` 归为 `edit`。
6. **等界面稳定**：动作返回前，等待目标窗口的 UIA 树哈希稳定（连续两次采样相同，最多 400ms），并写入 `effect.evidence`。
7. **可见性闸**：点击前检查 `IsOffscreen=false && IsEnabled=true`，否则先滚动/展开或返回 `element_unavailable`（不发盲点）。

### P2（更远）

8. **名称归一**：去零宽字符、去 `(&H)` 快捷键后缀、全半角归一；模糊匹配（前缀/包含）分级，命中多个返回 `ambiguous`。
9. **观察-动作-复核**循环内置到 `act` 的可选 `verify` 参数（目前靠 verify-contract 外部）。
10. **坐标点击的 DPI 单点收口**：所有坐标统一走 pet-core 的物理坐标入口，PowerShell 侧不再自己 SetCursorPos（本轮已验证 PowerShell 会踩 150% 缩放）。

## 4. 判据

| 改进 | 判据 |
|---|---|
| 自动 focus 重试 | 前台被占时 `act click` 单次调用成功率从 0 → 100%（同一动作）；只重试 1 次（回执可见 attempt=2） |
| pid 前台校验 | 主窗+模态场景不再误拒（本轮场景可复现） |
| 三级回落 | 「开发人员模式」类按钮可点（PowerShell 侧已复现不支持 Invoke） |
| act snapshot | 与 `see tree` 元素数量/名称一致（单测比对） |
| 等稳定 | 动作后 300ms 内读树不再出现旧状态（用对话框场景复测） |

## 5. 独立性

- 全部实现在 `game-control.js` + `pet-core`（Rust）；**不引入 ZCode 的任何接口**。
- ZCode CUA 只作为「读」的参照与人工操作的备用，不进入运行时链路。
- 三层注入与 veto 码体系保留；新增的自动 focus/回落只在 `act` 内部，不改变对外动作语义。
