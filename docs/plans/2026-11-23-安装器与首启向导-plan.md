## 1. 三形态对比（实测结论）

| 形态 | 复用度 | 工作量 | 风险 | 结论 |
|---|---|---|---|---|
| **A. `install-wizard.mjs` 交互向导**（Node，无新依赖） | 高：直接复用 bootstrap 23 项/`fix`/`--json`、`fetch-models`、`check-models`、`start-embed`、launcher | 中 | 低（纯本地；无 UI 依赖） | **首选，第一期** |
| B. Electron 首启页 | 中：可复用 control-v2 样式/`config-persist`/IPC；但 `config-loader.js:39` 无 config 即抛错，需独立入口 | 中高 | 中（要起 Electron 才能配 Electron） | 二期 |
| C. NSIS EXE | 中：`_packaging` 已有可用 NSIS（产出 110MB Setup），但**只含 live-2d，不含 Python/服务/模型** | 高 | 高（下载 ~10GB、签名/杀软/路径） | 三期：薄壳（装代码 + 调 A） |

## 3. 降级矩阵（无本地模型/无 Docker 时必须明确提示，不静默）

| 缺什么 | 影响 | 向导表现 | 最低可用性 |
|---|---|---|---|
| LLM key | 不能聊天 | 必填，否则阻塞 | — |
| Docker/8090 嵌入 | MemOS 长记忆不可用（聊天仍可）；公开版把 embed 从 required 降为 warn | 黄条提示「记忆降级」 | ✅ 聊天+TTS+字幕+人格 |
| Ollama 本地视觉 | 看屏走云 provider（`vision.tiers.fallbackToProvider` 默认 true）；OCR 失效 | 黄条 | ✅ |
| ASR 模型 | 按住 V 无反应 | 黄条 | ✅ |
| moc3/Cubism Core | 皮套不显示（只剩字幕/控制中心） | **红条 + 官方获取指引** | 仅文字 |
| MemOS 子树（公开版不含） | 记忆/日记/知识库降级 | 黄条 + 说明 | ✅ |
| pet-core 未编译 | PowerShell 兜底，慢约 20 倍 | 黄条 | ✅ |
| LumenAct | 8120 关，表情规则兜底 | 黄条 | ✅ |

## 4. 公开版必须同步的 3 个判据改动（E 副本内）

1. `bootstrap` 第 20 项 `embed`：required → **warn**（无 Docker 不判红）。
2. `services.json`：`memos.required` true → **false**（公开版不含 MemOS 子树）。
3. 新增 `assets.selfsupply` 检查：moc3 / Cubism Core / MemOS 缺 → 明确「自备」文案，而不是崩溃。

## 5. 交付物与验收

- `scripts/install-wizard.mjs`：交互（TTY）+ 非交互（`--yes --provider=... --key-env=... --json`）；失败非零退出。
- `docs/安装-首启向导-2026-11-23.md`：步骤、截图位、故障排查。
- 验收（只在 E 副本/临时目录）：
  1. 全新目录从 0 走到「聊天可用」，日志零 key 回显；
  2. 故意填错 key → 401 文案明确、可重填；
  3. 中途 Ctrl+C → 不留半写配置（原子写 + 备份）；
  4. 无 Docker/无 Ollama/无 moc3 → 按降级矩阵提示，不崩；
  5. 二次运行 → 识别已装，只补缺项（幂等）。
