# 设计：状态源通道（2026-11-14）

> 范围：回答「怎么知道游戏状态」的通道选型与最小落地骨架。**本文不改任何代码**，只写这一份设计稿。
> 前置阅读：`docs/设计-状态仲裁-FactStore-2026-11-14.md`（仲裁细节）、`docs/设计-纯视觉游戏操作框架-2026-11-14.md`（视觉闭环）、`docs/评估-PVZ内存读可行性-2026-11-10.md`（内存读实测）。
>
> 证据标记：`[实]` = 本机文件/端口/代码/日志实际看到；`[文]` = 官方文档/模板/API；`[推]` = 从代码、协议或运行时原理推导，未直接实测。
>
> **一句话结论：Mod 优先，RCON 只对专服兜底，日志只做低频事实，内存不做，UIA 只用于启动器/菜单。**

---

## 0. 五条结论

1. **先做 Fabric 只读导出 Mod（P0）。** 接收端已经存在：`js/core/mod-provider.js` 在 `127.0.0.1:8123` 收「一行一个 JSON」，`fact-store.js` 已按 `mod > api > vision > replay` 仲裁，`game-loop.js` 的 HUD 闸已优先采信新鲜的 mod `player.hp`。缺的只是游戏里那半边。Fabric 侧 2-3 天可出 MVP（含真机调试）。`[实]`
2. **内存读取不做（P3，只留接口名）。** MC 是 Java 堆 + 分代/压缩 GC，裸 `ReadProcessMemory` 能读到字节，但读不到「哪个对象拥有这个值」；PVZ 的实测已经证明，连一个自己造的标量都收敛不到唯一地址（89 → 44 个候选），结构化草坪状态更不可能。`[实/推]`
3. **RCON 只对自有专服成立（P1，默认关闭）。** 单机集成服务器没有 RCON 入口；现有 `minecraft-rcon.cjs` 的限速是 200ms/条、120 条/分钟（≈1.5Hz），只够兜底 hp/坐标，不够战斗反应。`[实/推]`
4. **日志/回放只做 `replay` 低频事实源（P2）。** MC 的 `latest.log`、`stats/*.json`、`advancements/*.json` 能回答「死了几次、杀了什么、走到哪」，回答不了「现在第几格有僵尸」；适合人设记忆与复盘，不做实时决策。`[实]`
5. **视觉永远在。** Mod 提供「是什么」（精确状态），视觉提供「动作有没有生效 / 窗口是否前台 / 是否在菜单」。任何单一通道都不能绕过安全闸；`checkSafetyGate` 的前台、场景、GUI 三条判据仍然由视觉负责。`[实]`

## 2. 通道对比表

> 精确度是「对该通道能拿到的状态」的相对判断，不是绝对百分比；延迟指「状态变化 → 桌宠可读」的典型量级。

| 通道 | 精确度 | 延迟 | 实现成本 | 维护成本 | 风险 | 适用条件 |
|---|---|---|---|---|---|---|
| **① 进程内 Mod**（Fabric/NeoForge） | ★★★★★ 服务端权威值：hp/food/pos/inventory/entities 都是精确值 `[推]` | 采样 50-100ms + 回环传输 <1ms（10-20Hz） `[推]` | 2-3 人日 MVP；约 300-400 行 Java + 5 个文件 `[推]` | 每个 MC 大版本 0.5-2 人日；mappings/API 变动是主成本 `[推]` | 低：官方扩展点、只读、单机/自建服 `[文]` | 游戏有官方 Mod API、能装 loader、单机或自有服务器 |
| **② 内存读取**（ReadProcessMemory） | ★★☆ 标量可读；结构化对象图不可靠（Java GC） `[实/推]` | 单次读 1-10ms；定位/重定位 秒-分钟；更新后重来 `[实/推]` | 2-6 周/游戏；扫描器 + 指针链 + 版本适配 `[推]` | 每次游戏更新都可能失效；最高 `[推]` | 高：反作弊/ToS/法律灰区/杀软误报 `[文/推]` | 仅单机、无 AC、用户书面授权、只读；否则**不做** |
| **③ RCON**（MC 服务端命令） | ★★★★☆ 服务端权威，但受命令/文本解析限制 `[推]` | 1 tick（50ms）+ 限速；现有 1.5Hz（200-700ms） `[实]` | 0.5 人日；客户端已有 `[实]` | 低：命令语法稳定 `[推]` | 中低：明文、op 级、可改世界；只读白名单 + 回环 `[文/推]` | 自有专服、`enable-rcon=true`；**单机不适用** |
| **④ 官方本地 API**（Valve GSI / LoL / SimConnect） | ★★★★☆ 游戏定义，通常 90-99% `[文]` | GSI ~100ms push；LoL ~100-1000ms poll；SimConnect ~10-50ms `[文/推]` | 0.5-2 人日/游戏 `[推]` | 低-中：API 版本变化 `[推]` | 低：官方、本地 `[文]` | 游戏自带本地 API；**MC 客户端没有** |
| **⑤ 日志/回放**（log/stats/replay） | ★★ 事件/统计，不是实时状态 `[实]` | `latest.log` <1s；stats 分钟级/退出时；replay 赛后 `[实/推]` | 0.5 人日/游戏 `[推]` | 中：格式/轮转/编码变化 `[推]` | 低：隐私、陈旧数据 `[推]` | 低频事实、复盘、人设记忆 |
| **⑥ UIA 语义树** | ★ 仅窗口元数据；游戏画布无子元素 `[推]` | 40-100ms；可能挂起 `[实/推]` | 0（已有 `uia.rs`） `[实]` | 低-中：UI 布局变化 `[推]` | 低：权限/UIPI/挂起 `[推]` | 启动器、菜单、标准控件；**不是游戏状态通道** |

**读表要点：**
- 「精确度」和「延迟」不能只看单个数字：Mod 的 50ms 是采样粒度，不是端到端 50ms；RCON 的 200ms 是现有客户端的保守限速，不是协议上限 `[推]`。
- 「实现成本」不含状态层：状态层已经由 `fact-store.js` / `mod-provider.js` 付过了 `[实]`。
- 内存读取虽然列在表里，但结论是**不做**；它存在的意义是让「为什么不做」有对照 `[推]`。

## 3. ① 进程内观测（Mod / 插件）

### 3.1 结论

**能落，且是最高优先。** 原因三条：
1. **官方扩展点**：Fabric/NeoForge 的 `mods` 目录是启动即加载，不需要像 PVZ 那样在游戏内手动点「启用」；PVZ 那一轮就是卡在 Mod 管理器的人工开关上 `[实]`。
2. **数据最准**：单机时客户端和集成服务器在同一个 JVM，服务端玩家对象是权威值；hp、food、pos、inventory、实体列表都能直接读 `[推]`。
3. **接收端已经在了**：协议、端口、仲裁、HUD 闸都接好了，生产者只要按现有字段发 JSON `[实]`。

Fabric 与 NeoForge 都能做；**首选 Fabric**，原因见 3.2。

### 3.2 Fabric vs NeoForge

| 项 | Fabric（推荐） | NeoForge |
|---|---|---|
| 本机现状 | 未安装；libraries 里有旧 loader 0.16.9/0.18.x、intermediary 1.21.1 `[实]` | **已安装 21.1.251**，`versions/neoforge-21.1.251`，`inheritsFrom: 1.21.1`，mods 目录为空 `[实]` |
| 1.21.1 版本 | Loader **0.20.1**、Fabric API **0.116.17+1.21.1**、Loom **1.19-SNAPSHOT**、Java 21 `[文]` | NeoForge **21.1.251**、Java 21 `[实]` |
| 构建 | `fabric-loom-remap` 插件；`./gradlew build` `[文]` | ModDevGradle 2.x；`neoForge { version = "21.1.251" }` `[推]` |
| 入口 | `ClientModInitializer` + `ClientTickEvents.END_CLIENT_TICK` `[文]` | `@Mod` + `ClientTickEvent.Post` `[推]` |
| 直接启动 | 版本 JSON 只有 8 个库，`inheritsFrom: 1.21.1`；合并父 JSON 即可，`-cp` + `-DFabricMcEmu` `[实]` | 版本 JSON 47 个库 + `${library_directory}` / `--add-modules` 模块参数；现有 `launch-minecraft.py` 不支持，需 PCL 或补参数替换 `[实]` |
| 世界复用 | 可用 `--gameDir versions/1.21.1` 复用「新的世界」 `[推]` | 实例自带「New World」，与 1.21.1 的「新的世界」分离；需复制存档 `[实]` |
| 额外成本 | 装 loader + Fabric API（首次需联网） `[推]` | 无需装 loader；但启动器/世界迁移多 0.5-1 天 `[推]` |

**选 Fabric 的核心理由**：它的启动链路只是「多 8 个 jar + 一个 `-DFabricMcEmu`」，而 NeoForge 要处理模块路径和变量替换；对一个「只读导出」的小 Mod，Fabric 的版本耦合和启动成本都更低 `[实/推]`。

入口（20 行内，节流到 10Hz；TCP 写入在独立线程）：

```java
public final class McStateClient implements ClientModInitializer {
    private static final NdjsonServer OUT = new NdjsonServer(8123);
    private static int tick;

    @Override public void onInitializeClient() {
        OUT.start();                                  // 守护线程，连不上就重试
        ClientTickEvents.END_CLIENT_TICK.register(c -> {
            if (c.player == null || (++tick & 1) != 0) return;   // 每 2 tick = 10Hz
            OUT.offer(StateCollector.collect(c));                 // 只入队，不阻塞渲染线程
        });
    }
}
```

采集（字段名必须和 `mod-provider.js` 一致）：

```java
static String collect(Minecraft mc) {
    LocalPlayer p = mc.player;
    JsonObject o = new JsonObject();
    o.addProperty("t", System.currentTimeMillis());
    o.addProperty("hp", p.getHealth());
    o.addProperty("maxHp", p.getMaxHealth());
    o.addProperty("food", p.getFoodData().getFoodLevel());
    o.addProperty("x", p.getX()); o.addProperty("y", p.getY()); o.addProperty("z", p.getZ());
    o.addProperty("dim", p.level().dimension().location().toString());
    // entities：mc.level.getEntitiesOfClass(Entity.class, p.getBoundingBox().inflate(24), e -> e != p)
    //          每个输出 {"type":"minecraft:zombie","dist":3.2}
    // inventory：p.getInventory().getContainerSize() / getItem(i)
    //          每个输出 {"slot":i,"id":"minecraft:bread","count":3}
    return GSON.toJson(o);
}
```

回环发送（骨架；真实实现要处理重连、背压、关闭）：

```java
final class NdjsonServer {
    private final Queue<String> q = new ConcurrentLinkedQueue<>();
    void start() {
        new Thread(() -> {
            while (true) {
                try (ServerSocket ss = new ServerSocket()) {
                    ss.setReuseAddress(true);
                    ss.bind(new InetSocketAddress(InetAddress.getLoopbackAddress(), 8123));
                    try (Socket s = ss.accept()) {
                        s.setTcpNoDelay(true);
                        var w = new BufferedWriter(new OutputStreamWriter(s.getOutputStream(), UTF_8));
                        while (!s.isClosed()) {
                            String line = q.poll();
                            if (line == null) { Thread.sleep(2); continue; }
                            w.write(line); w.write('\n'); w.flush();
                        }
                    }
                } catch (Exception ignored) { try { Thread.sleep(2000); } catch (Exception e2) { } }
            }
        }, "dsh-state-tx").start();
    }
    void offer(String line) { if (q.size() > 200) q.poll(); q.offer(line); }  // 背压：丢最旧
}
```

> `Gson` 是 MC 自带依赖（`com.google.gson`），不用额外加；`Gson GSON = new Gson();` 放在采集类里即可 `[推]`。

### 3.5 它能精确吐出什么

> 「服务端」= 单机集成服务器或自建专服；「客户端」= 多人游戏里客户端只能看到服务器同步给你的部分 `[推]`。

| 状态 | 数据源 | 精度 | 备注 |
|---|---|---|---|
| hp / maxHp / 吸收 | 玩家实体 | float，精确 | 视觉只能数心形；Mod 直接读数值 `[推]` |
| 饥饿 / 饱和度 / 疲劳 | `FoodData` | int / float，精确 | 视觉完全读不到 `[推]` |
| 经验 / 等级 | 玩家 | int，精确 | — |
| 坐标 / 速度 / 朝向 | 玩家 | double / float，精确 | 自己的坐标精确；其他实体是同步值 `[推]` |
| 维度 / 游戏模式 | 玩家 | 字符串/枚举，精确 | `minecraft:overworld` / `the_nether` / `the_end` |
| 背包（41 格） | `Inventory` | 物品 id/数量/损伤，精确 | 1.21.1 用数据组件；MVP 只出 id/count `[推]` |
| 选中槽位 | `Inventory.selected` | int，精确 | 换手/切物品能立刻知道 |
| 打开的容器 | `player.containerMenu` | 已打开容器的槽位精确 | 箱子未打开时客户端不知道内容；服务端可读 `BlockEntity` `[推]` |
| 实体列表 | 世界 | 类型/坐标/距离精确 | 服务端可见已加载区块内全部；客户端只可见追踪范围内 `[推]` |
| 实体血量 | `LivingEntity` | 同步元数据 | 对其他玩家/部分服务器不要依赖；怪物通常可读 `[推]` |
| 方块交互目标 | `mc.hitResult` | 客户端射线结果 | 与服务端可能有延迟/触及距离差异；当「意图」用 `[推]` |
| 方块状态 / 光照 | 世界 | 已加载区块精确 | 客户端只知道自己收到的区块 `[推]` |
| 时间 / 天气 / 难度 | 世界 | 精确 | — |
| TPS / MSPT / 种子 | 集成服务器 | 精确 | 仅单机/自有服；多人客户端没有 `[推]` |
| 计分板 / Boss 条 / 聊天 / 成就 / 统计 | 客户端/服务端 | 精确 | 聊天可做事件；Boss 条可做战斗状态 |
| 当前界面 / 按键状态 | 客户端 | 精确 | 比模板匹配更可靠地判断「在背包/在菜单」 `[推]` |
| 死亡 / 重生 | 玩家 | 精确 | 可直接替代 `death` 场景模板 |

**边界**：
- 多人游戏里客户端 Mod 只能看到服务器同步的数据；这不是「读不到」，是「服务器没发」 `[推]`。
- 客户端实体坐标是 20Hz 同步 + 插值；做决策用服务端值，做渲染才用插值 `[推]`。
- 背包 NBT/组件完整输出会把包变大；MVP 只出 `id/count/damage`，需要时再扩 `[推]`。
- 不要输出服务端种子、其他玩家 IP、聊天全文到外部；这些是隐私/作弊面 `[推]`。

### 3.6 怎么把数据送出游戏

| 方式 | 延迟 | 可靠性 | 实现量 | 结论 |
|---|---|---|---|---|
| **TCP 回环 + NDJSON** | 采样后 <1ms | 高；有序；断线可重连 | ~80 行 | **主通道**；直接对接 `mod-provider.js` `[实]` |
| **原子文件快照** | 写 1-5ms + 读轮询 50-250ms | 高；无端口/防火墙 | ~30 行 | **兜底/崩溃诊断**；PVZ 已验证 500ms 原子写 `[实]` |
| HTTP（JDK `HttpServer`） | 1-5ms | 高 | ~40 行 | 可选调试端点；不做主通道 `[推]` |
| UDP | <1ms | 丢包/乱序 | ~40 行 | 不推荐；状态帧丢一帧不如不丢 `[推]` |
| 命名管道 | <1ms | 高 | Java 无标准 API | 跳过 `[推]` |
| 日志 tail | 10-100ms | 轮转/半行/阻塞 | ~30 行 | 不推荐；Mod 不需要这么绕 `[推]` |

**线路格式**（必须与 `mod-provider.js` 现有字段一致）：

```json
{"t":1731600000000,"hp":18.0,"maxHp":20.0,"food":17,
 "x":12.3,"y":64.0,"z":-8.1,"dim":"minecraft:overworld",
 "entities":[{"type":"minecraft:zombie","dist":3.2}],
 "inventory":[{"slot":0,"id":"minecraft:bread","count":3}]}
```

可选扩展（接收端现在会忽略未知字段；要用需同步改 `mod-provider.js`，对应 FactStore 设计里的 D5/D6）：
- `seq`：单调递增，防跳变/回绕 `[推]`。
- `instance:{hwnd,pid,world}`：双开/切窗时防止事实串局 `[推]`。
- `sat` / `xp` / `level` / `sel` / `dead` / `scene` / `target`：更细的状态；MVP 不做 `[推]`。

### 3.7 版本、依赖、PCL 共存

**Fabric 1.21.1 依赖（官方示例模板 `[文]`）：**
- Fabric Loader `0.20.1`
- Fabric API `0.116.17+1.21.1`
- Loom `1.19-SNAPSHOT`
- Java 21（本机 MC 1.21.1 的 `javaVersion.majorVersion=21` `[实]`）
- Gradle wrapper（模板自带；首次构建会下载 MC、mappings、Fabric API）

**PCL 支持 Fabric 吗：支持。** PCL2 可自动安装 Fabric/Quilt/NeoForge/Forge；用户需要做的是：
1. 在 PCL 的版本设置/下载页选 1.21.1 + Fabric Loader 0.20.1，安装出一个 Fabric 版本 `[文/推]`。
2. 下载 Fabric API `0.116.17+1.21.1` 放进 mods 目录 `[文]`。
3. 把我们的 `dsh-mc-state-0.1.0.jar` 放进同一个 mods 目录 `[推]`。
4. 用 PCL 启动 Fabric 版本；或在自定义启动器里用 `--gameDir` 指回 `versions/1.21.1` 复用「新的世界」 `[推]`。

**mods 目录在哪（本机实测）：**
- `.minecraft/mods` 为空；`versions/1.21.1/mods` 不存在；`versions/neoforge-21.1.251/mods` 为空 `[实]`。
- PCL 配置里 `LaunchArgumentIndieV2:4`、实例 `Setup.ini` 里 `VersionArgumentIndieV2:True`，说明版本隔离是开着的；隔离开启时 mods 在 `versions/<版本名>/mods`，关闭时才在 `.minecraft/mods` `[实/推]`。
- 因此装完 Fabric 后，最稳的是看 PCL 的「版本设置 → 模组管理」指向哪个目录，不要猜 `[推]`。

**直接启动的坑（`launch-minecraft.py`）**：
- 该脚本只读目标版本自己的 JSON，`build_classpath` 只遍历该 JSON 的 `libraries` `[实]`。
- Fabric 的 profile JSON 是 `inheritsFrom: "1.21.1"`，只有 8 个库（asm/intermediary/loader/sponge-mixin），父版本有 97 个库；不合并父 JSON 会缺 vanilla 库，启动必失败 `[实]`。
- 还缺 `arguments.jvm` 里的 `-DFabricMcEmu= net.minecraft.client.main.Main`；以及父版本的 `assetIndex` `[实]`。
- 该脚本把 `--gameDir` 固定成 `versions/<args.version>`；启动 Fabric 版本时它会指向 Fabric 目录，世界里没有「新的世界」。要复用旧世界，需加 `--game-dir` 参数 `[实/推]`。
- NeoForge 更麻烦：47 个库 + `${library_directory}` / `${classpath_separator}` / `--add-modules` / `--add-opens`；现有脚本完全没处理 `arguments.jvm` `[实]`。所以 **NeoForge 用 PCL 启动，别用这个脚本** `[推]`。

**首次安装要联网**：本机 libraries 里只有旧 loader（0.16.9/0.18.x）和 intermediary 1.21.1，没有 0.20.1；Fabric API 1.21.1 也没有本地 jar `[实]`。如果网络受限，用 PCL 的下载源或提前把 jar 放进 `libraries`/`mods` `[推]`。

### 3.8 成本与维护

| 项 | 估算 | 依据 |
|---|---|---|
| Fabric MVP（只写文件） | ~180-220 行 Java + 60 行构建/清单；3-4 个文件 | 采集/序列化/原子写都很薄 `[推]` |
| Fabric MVP（TCP + 文件兜底） | ~300-400 行 Java；5-6 个文件 | 多一个发送线程、重连、背压 `[推]` |
| 首次构建 | 2-4 小时（含下载 MC/mappings/API） | Loom 首次要拉依赖 `[推]` |
| 真机调试 | 4-8 小时 | 装 loader、mods 路径、世界复用、防火墙、重连 `[推]` |
| 合计 | **2-3 人日** | 不含状态层改造 `[推]` |
| 跟版本 | 每个 MC 版本 0.5-2 人日 | Fabric API 事件稳定；mappings/字段改名是主成本 `[推]` |
| 停在 1.21.1 | 0 | 不升级就不用跟 `[推]` |

PVZ 的先例说明「文件导出」本身很便宜：122 行 C#、500ms 定时、tmp+move 原子写；贵的是游戏内 Mod 管理器的启用流程 `[实]`。Fabric/NeoForge 没有这个启用步骤，启动即加载，所以这条路比 PVZ 顺 `[推]`。

### 3.9 坑与风险

1. **不要用 Mixin 进游戏逻辑**：MVP 只用 Fabric API 的 tick 事件；Mixin 会把版本耦合和崩溃面放大 `[推]`。
2. **不要阻塞渲染线程**：socket 写入、文件写入、JSON 大对象序列化都不要在 tick 回调里做；用队列 + 发送线程 `[推]`。
3. **接收端只接受一个客户端**：`mod-provider.js` 新连接会踢掉旧连接；双开时两个游戏会互相抢 8123。要么加 `instance` 字段并在接收端过滤，要么每个实例用不同端口 `[实/推]`。
4. **断线重连**：桌宠没开/重启时，Mod 的 connect 会失败；必须静默重试（2s），不能在游戏里报错/卡帧 `[推]`。
5. **背压**：接收端慢或断线时，队列不能无限长；MVP 上限 200 行，丢最旧 `[推]`。
6. **文件读锁**：Windows 上读方打开文件时，写方的 `ATOMIC_MOVE` 可能失败；读方要重试/退避，或写 `state.<seq>.json` 保留两份 `[推]`。
7. **防火墙**：监听回环通常不弹窗，但 Windows 防火墙策略因机器而异；弹了就允许「专用网络」，或用文件兜底 `[推]`。
8. **公共服规则**：只读状态导出在多数公共服仍可能被视作「信息优势」；单机/自建服用，公共服先问规则 `[文/推]`。
9. **EULA/Usage Guidelines**：Minecraft 对个人自用 Mod 宽松（"Personal use. We are very relaxed about things you create for yourself."） `[文]`；但不要分发游戏代码/资源，不要把 Mod 做成付费外挂 `[推]`。
10. **PVZ 的教训**：游戏自带 Mod 系统可能要求人工启用；Fabric/NeoForge 的 `mods` 目录没有这个坑，但版本/loader 不匹配会直接启动失败 `[实/推]`。

### 3.10 验收清单

- [ ] Fabric 版本能启动，日志里能看到 `dsh-mc-state` 已加载。
- [ ] `mod-provider.js` 的 `health()`：`connected:true`、`ageMs<1000`、`silent:false`、`parseErrs:0`。
- [ ] `fact-store` 里 `player.hp.source === 'mod'`，`resolveHudGate` 返回 `hpSource:'mod'`。
- [ ] 停掉 Mod 数据 3 秒 → 自动回落 `vision`，循环不中断、不报致命错。
- [ ] Mod 完全不在 → 视觉行为与现在逐字段一致（老 profile 零差异）。
- [ ] 文件兜底：`state.json` 永远是完整 JSON；读方在文件缺失/半写时重试成功。
- [ ] 双开测试：第二个实例不会把第一个实例的事实搅乱（靠 `instance` 或不同端口）。
- [ ] 全程只读：没有写游戏内存、没有发游戏包、没有改世界。

## 4. ② 内存读取（ReadProcessMemory）

### 4.1 结论

**能读，但不该落；本项目的结论是「不做」。** 只保留 `memory` 这个来源名（`fact-store` 的 `sourceRank` 里有 60），实现为零；`allowSources` 默认把它排除 `[实/推]`。

### 4.2 技术门槛

| 项 | 事实 | 对本项目的含义 |
|---|---|---|
| 打开进程 | `OpenProcess(PROCESS_VM_READ \| PROCESS_QUERY_INFORMATION, FALSE, pid)` 可读同用户、同会话、同完整性级别的进程 `[文/推]` | 单机 MC 没有保护，能打开；PVZ 实测一次成功 `[实]` |
| 权限 | 目标以管理员运行时，调用方也要管理员；跨用户要 `SeDebugPrivilege`；PPL/反作弊保护进程直接拒绝 `[文/推]` | 桌宠若常驻非管理员，遇到提权游戏就失败 |
| 位数 | 64 位调用方才能可靠读 64 位目标；32 位要用 `NtWow64ReadVirtualMemory64` `[文/推]` | pet-core 是 64 位 Rust，这点没问题 `[推]` |
| 枚举区域 | `VirtualQueryEx`，过滤 `MEM_COMMIT`、可读、非 `PAGE_GUARD`/`PAGE_NOACCESS` `[文/推]` | PVZ 扫描 4273 个区域、1765MB，单轮 13-27 秒 `[实]` |
| 读取 | `ReadProcessMemory`；跨页/保护页会部分失败 `[文/推]` | 读到字节≠读到语义 |

### 4.3 定位方案：静态偏移 vs 指针链 vs AOB，对 Java 都不现实

| 方案 | 在 C/C++ 游戏 | 在 MC（Java/HotSpot） |
|---|---|---|
| 静态偏移 | 模块基址 + 固定偏移，常用 | **不成立**：游戏状态是 Java 对象，不存在「模块数据段里的固定结构」 `[推]` |
| 指针链 | 静态根 → 多级指针，常用 | **不可靠**：静态字段在 `java.lang.Class` 镜像里，根在堆上；对象会被 GC 移动 `[推]` |
| AOB/特征码 | 找函数/结构，常用 | **只能找字节**：能找到类名字符串，但无法从字符串走到「拥有该字段的对象」；需要 GC 根/对象头/压缩 oops/类布局 `[推]` |

**PVZ 的实测（虽然不是 Java，但同样有托管堆）**：
- 无壳、无混淆、无 AC，`PROCESS_VM_READ` 一次成功；托管堆字符串可搜 `[实]`。
- 用「窗口尺寸」这个自己造的、可精确验证的标量做两轮差分：89 个候选 → 只剩 44 个跟随变化 `[实]`。
- 结论：**即使真值完全已知，也收敛不到唯一地址**；结构化「第 r 行第 c 列是什么植物」需要对象图，裸扫描做不到 `[实/推]`。
- MC 的堆更大、GC 会压缩/移动对象、还有压缩 oops；只会比 PVZ 更难 `[推]`。

### 4.4 风险清单

| 风险 | 说明 | 结论 |
|---|---|---|
| 反作弊（EAC/BattlEye/VAC） | 内核驱动、保护进程、`ObRegisterCallbacks` 剥离读句柄、特征扫描、调试器检测；绕过本身违反 ToS，可能违法 `[文/推]` | 任何带 AC 的游戏**绝对不碰** |
| 单机 MC | 没有 AC；但 EULA 对反编译/逆向有灰区；Usage Guidelines 对个人自用宽松 `[文]` | 技术上能，但没有必要（Mod 更好） |
| 公共服 | 服务器规则通常禁止信息优势/自动化的第三方工具 `[文/推]` | 不做 |
| 法律 | DMCA §1201 反规避、软件保护条例等；不是法律意见 `[推]` | 不分发、不商业化、不做绕过 |
| 杀软/EDR | 内存扫描器常被标成 HackTool/PUA `[推]` | 影响桌宠声誉 |
| 维护 | 每次游戏更新都可能失效；地址/偏移是负资产 `[推]` | 成本远高于 Mod |
| 数据正确性 | 读到旧地址/错误对象/半更新值；没有结构校验 `[推]` | 会产生「自信的错误」 |

### 4.5 什么条件下允许、什么条件下绝对不做

**允许（仅限「将来某个单机、无 AC 的原生 C++ 游戏，且 Mod/API 都没有」）：**
1. 用户对**具体游戏、具体用途**给出明确书面同意。
2. 只读：只申请 `PROCESS_VM_READ | PROCESS_QUERY_INFORMATION`；绝不 `VM_WRITE`/`VM_OPERATION`。
3. 绝不 `WriteProcessMemory`、绝不 `CreateRemoteThread`、绝不注入 DLL、绝不 hook、绝不内核驱动/DMA。
4. 只在本地运行；不联网上传；不记录/分发偏移；工具不随产品分发。
5. 有 kill switch 和审计日志；每次启动重新定位，不复用旧地址。
6. 先证明 Mod/API 都不可用，并把这个结论写进文档。

**绝对不做：**
- 任何 EAC/BattlEye/VAC 或其他反作弊保护的游戏。
- 任何多人/在线游戏。
- 任何写内存、注入、hook、内核驱动、DMA、hypervisor、绕过保护。
- 任何「自动扫描用户没点名的进程」。
- 把内存读取做成产品默认能力或卖给用户。

### 4.6 对状态层的具体处置

- `fact-store` 的 `sourceRank` 保留 `memory:60`，但 `allowSources` 推荐设为 `['mod','api','vision','replay']`（不含 `memory`） `[实/推]`。
- 不新增 `memory-provider.js`；不写扫描器；不引 `ReadProcessMemory` 依赖。
- 如果未来真要做，也应该是「一个独立实验工具」，不是桌宠的一部分 `[推]`。

## 5. ③ API / 协议

### 5.1 MC RCON：能读什么、频率、cheats、输入干扰

**能读（只读命令）：**

| 命令 | 返回 | 用途 |
|---|---|---|
| `data get entity <玩家> Health` | `20.0f` | hp；除以 maxHp（默认 20） `[推]` |
| `data get entity <玩家> foodLevel` | int | 饥饿；字段名以 1.21.1 实际 NBT 为准 `[推]` |
| `data get entity <玩家> Pos` | `[x, y, z]` | 坐标；现有 `playerPos()` 已解析 `[实]` |
| `data get entity <玩家> Dimension` | `"minecraft:overworld"` | 维度 `[推]` |
| `data get entity <玩家> Inventory` | 列表（大） | 背包；高频别用，序列化很贵 `[推]` |
| `data get entity <玩家> SelectedItemSlot` | int | 选中槽 `[推]` |
| `data get entity <玩家> XpLevel` | int | 等级 `[推]` |
| `list` | 在线玩家 | 是否在线 `[实]` |
| `time query daytime` / `weather query` | int / 字符串 | 世界时间/天气 `[推]` |
| `data get block <x> <y> <z>` | 方块实体 NBT（若有） | 箱子等 `[推]` |

**频率：**
- RCON 命令在服务端线程执行；没有协议级硬上限，但每条都吃 tick 时间 `[推]`。
- 现有 `minecraft-rcon.cjs` 的 `rateGate`：200ms/条 + 120 条/分钟 ≈ 1.5Hz `[实]`。
- 建议：hp/pos 1.5Hz 够用；战斗反应交给视觉 20Hz；不要用 RCON 追高频 `[推]`。
- `data get entity @p Inventory` 这类大 NBT 不要放进 1.5Hz 循环；需要时单独低频拉 `[推]`。

**要不要 cheats：**
- 专服：RCON 是控制台级（op level 4），不需要开 `allow-cheats`；`enable-rcon=true` + `rcon.password` 即可 `[文/推]`。
- 单机：`/data` 需要世界开 cheats；但**单机根本没有 RCON**，所以这条不成立 `[推]`。

**对玩家输入的干扰：**
- RCON 是带外 TCP，不发键鼠、不打开聊天框，**不打断移动** `[推]`。
- 对比 `pet-runtime/tools/mc_cmd.py`：它用 `T` + `WM_CHAR` 打字，会打开聊天框；聊天框开着时移动会停，且 Esc/T 是状态机，容易把菜单打开 `[实]`。这是 RCON 的明确优势。

**单机为什么没有：**
- 集成服务器（`IntegratedServer`）不启动 RCON 线程；`server.properties` 的 `enable-rcon` 是专服配置 `[推]`。
- 开 LAN 世界也不是 RCON；它只是把集成服务器暴露到局域网 `[推]`。
- 所以「单机 MC 用 RCON」这条路不成立；单机的等价物是 Fabric/NeoForge 的**服务端侧 Mod**（也就是通道 ①） `[推]`。

### 5.2 Spigot/Paper 路线：单机有没有等价物

- Spigot/Paper 是**专服实现**，插件跑在专服进程里；单机存档不能被 Paper 直接加载成插件环境 `[文/推]`。
- 单机的等价物：
  1. **Fabric/NeoForge Mod**（推荐）：跑在集成服务器/客户端同一 JVM，直接读服务端玩家对象 `[推]`。
  2. **本地开一个 Paper 服，客户端连进去**：插件可以读精确状态、暴露 HTTP/WebSocket；但这是另一套世界/开服/内存开销，且存档要迁移 `[推]`。
- 结论：如果目标是「单机陪玩」，不要绕 Paper；用 Mod `[推]`。

### 5.3 通用官方本地 API 的形状

| API | 游戏 | 形状 | 延迟/频率 | 配置/入口 |
|---|---|---|---|---|
| **Valve GSI** | CS2 / Dota 2 | **push**：游戏 HTTP POST JSON 到本地端点 | ~100ms；`buffer`/`throttle` 可调 `[文]` | 游戏目录放 `gamestate_integration_*.cfg`，写 `uri`、`timeout`、`buffer`、`throttle`、`heartbeat`、`auth.token`、`data` `[文]` |
| **LoL Live Client Data API** | League of Legends | **poll**：`GET https://127.0.0.1:2999/liveclientdata/allgamedata` | 游戏内约 10Hz 更新；轮询 0.1-1s `[文/推]` | 游戏运行时自动开启；自签名证书 `[文]` |
| **MSFS SimConnect** | Microsoft Flight Simulator | **IPC/事件**：本地 SDK，不是 HTTP | 10-50ms 级 `[推]` | 官方 SDK；客户端库 `[文]` |

**形状启示：**
- 官方本地 API 不全是 HTTP：有 push（GSI）、poll（LoL）、IPC（SimConnect） `[文]`。
- 因此 Provider 抽象不能只写「TCP 客户端」，要支持 `push` / `poll` / `file` 三种模式 `[推]`。
- MC 没有「客户端本地状态 API」；它的官方协议是服务端 RCON，不是给单机客户端用的 `[推]`。

### 5.4 结论

- **RCON 只对自有专服成立**；默认关闭；`source` 建议归到 `api`（rank 80）或显式加 `rcon:75`，不要用未知来源（默认 40，低于 vision 50） `[实/推]`。
- 通用官方 API 只在「真的要做那款游戏」时接；每个 0.5-2 人日；不要预写一堆用不上的适配器 `[推]`。
- 单机 MC 走 Mod，不走 RCON/Paper `[推]`。

## 6. ④ 日志/事件文件 + UIA

### 6.1 MC 日志/统计/存档：能当低频事实源

| 文件 | 内容 | 更新频率 | 实时性 | 结论 |
|---|---|---|---|---|
| `logs/latest.log` | 聊天、死亡、加入/离开、成就、命令输出、错误 | 行缓冲，秒级 | <1s | 可 tail 做事件流；不是状态 `[实]` |
| `saves/<世界>/stats/<uuid>.json` | `killed_by` / `mined` / `custom`（deaths、play_time、walk_one_cm…） | 存档/退出时（本机 17:37 保存） | 分钟级 | 做长期人设/复盘 `[实]` |
| `saves/<世界>/advancements/<uuid>.json` | 已解锁成就 | 存档时 | 分钟级 | 事件/里程碑 `[实]` |
| `saves/<世界>/level.dat` | 种子、出生点、时间、天气（gzip NBT） | 存档时 | 分钟级；运行中可能旧 | 离线读世界信息 `[实]` |
| `saves/<世界>/playerdata/<uuid>.dat` | 玩家 NBT（位置、背包等） | 存档/退出时 | 分钟级 | 离线快照；不是实时 `[实]` |

本机实测（2026-11-14）：
- `latest.log` 里有 `user被僵尸杀死了`、`已将自己的游戏模式设置为创造模式`、`Saving and pausing game...`；行首是 `[HH:mm:ss]`，没有日期 `[实]`。
- `stats/00000fff-...json` 的 `DataVersion` 是 `3955`，`minecraft:custom.deaths=5`、`killed_by.zombie=3`、`mined.jungle_leaves=4`；mtime 与存档保存时间一致 `[实]`。
- `level.dat` 是 gzip NBT，2301 字节 `[实]`。

**解析要点：**
- `latest.log` 会在重启时轮转成日期 `.log.gz`；tail 要检测文件变小/换文件并重开 `[推]`。
- 行可能半写；只处理以 `\n` 结尾的完整行 `[推]`。
- 编码 UTF-8；中文日志不要按 GBK 读 `[实]`。
- Windows 上文件可能被游戏占用；读失败要退避重试，不要忙等 `[推]`。
- stats/advancements 是「存档时」更新，不是实时；`ttl` 给分钟级 `[推]`。

### 6.2 其他游戏的可解析文件

| 游戏/文件 | 形状 | 实时性 | 用途 |
|---|---|---|---|
| Elite Dangerous `Journal.*.log` | JSON Lines，事件（Docked/Jumped/Scan/Bounty） | 实时（秒级） | 极好的低频事实源 `[文]` |
| Rocket League `.replay` | 赛后回放 | 赛后 | 复盘，不是实时 `[文]` |
| CS2 `.dem` | 赛后 demo | 赛后 | 复盘 `[文]` |
| LoL `.rofl` | 赛后回放 | 赛后 | 复盘 `[文]` |
| ETS2/ATS 遥测 | 官方 SDK/插件，不是 log | 实时 | 需要插件，另算一条通道 `[文]` |

**结论：** 日志/回放是 `replay` 源（rank 20），TTL 长，只做「发生了什么」和人设记忆，不做动作反馈 `[实/推]`。

### 6.3 UIA 对游戏窗口有用吗

**基本没用。**
- MC 的窗口是 GLFW/OpenGL，游戏内容画在一个原生窗口里；UIA 只能看到顶层 `Window`（标题、矩形、进程 id），看不到血条/坐标/背包格子 `[推]`。
- Java Access Bridge 只覆盖 AWT/Swing；MC 用 LWJGL/GLFW，不走 Swing `[推]`。
- 少数游戏通过 Unity Accessibility Plugin / Unreal Slate accessibility 暴露菜单，但这是例外，不能当通用能力 `[推]`。
- 对**启动器/菜单/标准控件**有用：PCL 是 WPF，UIA 能扫到按钮/列表；用来装 Fabric、选版本、开游戏是合适的 `[推]`。
- 坑：UIA 调用可能被目标 UI 线程卡住；用 `uia_elements_budgeted` 的超时/预算；目标以管理员运行时，调用方也要同权限（UIPI） `[实/推]`。

**结论：** UIA 不是游戏状态通道；保留给启动器/菜单自动化，不为游戏状态新增工作 `[推]`。

## 7. 抽象与接线

### 7.1 Provider 接口（建议）

```js
const channel = {
  name: 'mod',                  // mod | api | rcon | replay | vision
  mode: 'push',                 // push | poll | file
  facts: ['player.hp', 'player.food', 'player.pos', 'world.dimension', 'enemy.*'],
  maxHz: 20,
  latencyMs: 55,
  risk: 'low',                  // low | medium | high
  start(ctx) {},
  stop() {},
  health() { return { connected: true, ageMs: 40, silent: false }; }
};
```

- `push`：Mod/GSI，服务端主动发；`poll`：RCON/LoL，按 `maxHz` 拉；`file`：日志/回放，按 mtime/offset 读 `[推]`。
- `health()` 必须能回答「连着没、多久没数据、解析错误多少」；`mod-provider.js` 已经有这三个字段 `[实]`。

### 7.2 仲裁与降级

- **优先级**：`mod 100 > api 80 > rcon 75 > vision 50 > replay 20`；`memory` 不启用 `[实/推]`。
- **降级**：Mod 3 秒没数据 → `silent:true` → 回落 vision；RCON 超时/密码错 → 回落 vision；任何通道挂掉都不能中断循环 `[实]`。
- **冲突**：Mod 与 vision 的 hp 偏差超过阈值 → `conflict:true` → 上层更保守（暂停/降速），**不要平均** `[实/推]`。
- **TTL**：hp 400-500ms、pos 400ms、dimension 5s、enemy 400ms、replay 分钟级；由事实声明，不由来源自带 `[推]`。
- **多实例**：Mod 信封可选 `instance:{hwnd,pid,world}`；接收端不匹配就丢弃，防双开串局 `[推]`。

### 7.3 安全闸的分工

```
Mod/API → 事实（hp/food/pos/entities）
Vision  → 事实（scene/gui/foreground/motion）+ 动作验证
SafetyGate = 抓帧成功 && 前台匹配 && 非阻塞场景 && 非 GUI 面板 && HUD 可读
             ↑ Mod 只能把「HUD 可读」这一项变真；
               前台/场景/GUI 仍由视觉判，不能绕过
```

- 这条分工是现有代码的行为：`resolveHudGate` 只改 `hpValid`；`checkSafetyGate` 仍看 `fgMatch`、`sceneBlocking`、`guiFlat` `[实]`。
- 不要让 Mod 直接触发动作；Mod 只出事实 `[推]`。
- 动作验证优先用视觉区域差分/帧差；没有验证就记 `unverifiable`，不要写 `verified:true` `[实/推]`。

## 9. 风险与红线

| 风险 | 通道 | 触发条件 | 对策 |
|---|---|---|---|
| 反作弊封禁 | 内存 | 任何 EAC/BattlEye/VAC 游戏 | **绝对不做**；不绕过、不注入、不驱动 `[文/推]` |
| ToS/EULA | 内存/Mod | 公共服、商业化、分发 | 单机/自建服；只读；不分发游戏代码；公共服先问规则 `[文/推]` |
| 杀软误报 | 内存 | 扫描器/注入器 | 不做；不分发 `[推]` |
| 明文 RCON 泄露 | RCON | 绑 0.0.0.0/公网 | 只绑回环；强密码；防火墙；不记录密码 `[文/推]` |
| RCON 改坏世界 | RCON | 放行 `fill/setblock/kill` | 只读白名单；`allowWorldModify` 默认 false `[实]` |
| Mod 被公共服视为作弊 | Mod | 多人公共服 | 单机/自建服；只读；提前问规则 `[文/推]` |
| 双开串局 | Mod | 两个客户端抢 8123 | `instance` 校验或每实例不同端口 `[推]` |
| 文件半写/读锁 | Mod 文件 | Windows 并发读 | tmp+ATOMIC_MOVE；读方重试；seq 文件 `[推]` |
| 日志隐私 | 日志 | 聊天/路径/玩家名 | 本地只读；不上传；保留期限 `[推]` |
| UIA 挂起 | UIA | 目标 UI 线程忙 | 预算/超时；不在 tick 主路径调用 `[实/推]` |
| 通道绕过安全闸 | 全部 | 只信 Mod 不看视觉 | 视觉仍判前台/场景/GUI；Mod 只补事实 `[实]` |

**红线（写进实现评审）：**
1. **不写内存**：没有 `WriteProcessMemory`、没有 `VM_WRITE`/`VM_OPERATION`。
2. **不注入**：没有 `CreateRemoteThread`、没有 DLL 注入、没有 hook、没有内核驱动、没有 DMA/hypervisor。
3. **不碰反作弊**：不在 EAC/BattlEye/VAC/任何 AC 游戏上做内存读取；不研究绕过。
4. **不远程**：Mod/RCON 只绑 `127.0.0.1`；不上公网、不做远程控制。
5. **不越权**：Mod 只出事实，不发游戏包、不改世界、不替玩家做动作。
6. **不自动扫描**：不扫描用户没点名的进程；内存通道不默认开启、不随产品分发。
7. **不单通道放行**：任何通道都不能单独绕过 `checkSafetyGate`；视觉的 `fgMatch`/`sceneBlocking`/`guiFlat` 必须保留。
8. **不伪造成功**：没有验证就写 `unverifiable`，不写 `verified:true`。
