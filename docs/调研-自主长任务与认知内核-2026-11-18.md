# 调研：自主长任务与认知内核（2026-11-18）

> 范围：只调研与设计，不改产品代码。外部源码全部 `git clone --depth 1` 到 `_research/autonomy-cognition/`（已 gitignored），
> 下文外部路径相对该目录；本地路径中 `live-2d/` 指 `_incoming/my-neuro/live-2d/`（与 ADR-006 同口径）。未核到的写进 §6，不猜。
> 对齐：`ADR-004`（成本/缓存红线）、`ADR-006`（planner 分层）、`ADR-007`（验证与恢复）、`ADR-010`（记忆 v2）；
> 与同批 `docs/调研-世界感知Phase2-4-2026-11-18.md`、`docs/调研-电脑操控Agent-2026-11-18.md` 共用词汇，不另起一套。

**结论摘要**

1. **我们不缺「循环」，缺「目标态 + 外部判据」**。宿主已有 30 轮工具循环（`_incoming/my-neuro/live-2d/js/ai/llm-handler.js:377`），
   缺的是「这次任务算不算完成、要不要继续」——OSWorld 与 τ-bench 都证明：长任务成功必须是**外部状态的纯函数**，不能问模型。
2. **认知内核不是新进程，是一个宿主插件**：`mind-kernel` 持有目标栈，30s 跑一次纯规则定向；计划仍按 ADR-006 放 `dispatch`。
   「做不做/停不停」由规则决定，「下一步做什么」由 LLM 决定——这是与 AutoGPT 最本质的分界。
3. **四条记忆已有三条半**：working（目标/计划）缺、episodic（`episode-store`）有、semantic（`user-facts`/知识库）有、
   procedural（`skill-library` + `pitfalls.json`）已有雏形；本轮补的是**目标态**与**经验闸门**，不是再建一套库。
4. **「学会」= 两次独立成功 + oracle 通过 + 可重放 + 可降级**，一次成功只算候选。Voyager 的 critic 闸门与 Reflexion 的
   按任务作用域，是防技能库污染的两条硬证据。
5. **最该否掉**：常驻自主循环（AutoGPT/BabyAGI 的无限任务生成）与「模型自评成功」。前者已被 AutoGPT Classic
   官方标为 unsupported、BabyAGI README 明写「infinite loop + 高 API 消耗」；后者是本项目 `复盘-真假成功` 已定性的病。

## 2. 她的认知循环：一次「她决定做点什么」的完整闭环

```
用户输入 / 世界事件 / 开放回路到期 / 任务结束
              │
        [1 感知]  WorldStore 快照 + 最近变化 + 输入事件          1s（已有）
              │
        [2 定向]  mind-kernel 30s 规则节拍：目标打分 / 预算 / 熔断 / 活动门   0 LLM
              │
        [3 选目标] 用户 > 到期开放回路 > 进行中目标 > 好奇（默认关）
              │
        [4 计划]  dispatch plan-store：首次 / 失败 / 偏离才调 LLM（ADR-006）
              │  ≤80 tokens 差分注入（只进最后一条 user）
        [5 执行]  现有 30 轮工具循环 + dispatch 12 动作（底层 36）+ grounding 四档
              │  每次动作后 T1（verify-contract，已有）
        [6 验证]  子任务 T2 / 任务 T3（ADR-007）
              │
        [7 恢复]  五级阶梯 + 两条熔断（ADR-007）
              │
        [8 沉淀]  task-episode + lesson + skill candidate（ADR-012）
              │
        [9 表达]  speech-budget 放行才说；否则写记录、不打扰（已有）
```

| 步 | 用什么（现有/新增） | 节拍 | 失败/否决时 |
|---|---|---|---|
| 1 感知 | **已有** `world-store.js`（TTL 事实、五态活动机、变化历史）+ Phase 2 浏览器/RSS | 1s | 采样器坏只少一行，不影响主链（ADR-004） |
| 2 定向 | **新增** `mind-kernel/arbiter.js`：目标评分、预算检查、熔断状态、活动门 | 30s（仅当有 goal 时）+ 事件 | 规则异常只跳过本次 tick，不阻塞对话 |
| 3 选目标 | **新增** `mind-kernel/goal-store.js`：目标栈 + 准入闸 | 事件驱动 | 无 `done_when` 的目标只能当 note，不能自主执行 |
| 4 计划 | **已有循环 + 新增** `dispatch/plan-store.js`（ADR-006） | 首次/失败/偏离 | 规划失败→降级为单步执行或 ask_user |
| 5 执行 | **已有** 30 轮循环、`dispatch`、grounding、`verify-contract` | 每轮工具调用 | 用户打断立即停（`llm-handler.js:408`） |
| 6 验证 | **已有 T1 + 新增 T2/T3**（ADR-007） | 动作后/子任务/任务结束 | 判失败→进恢复阶梯，不许自评通过 |
| 7 恢复 | **新增** 五级阶梯 + 两条熔断（ADR-007） | 失败时 | 连续失败→ask_user/fail，零副作用 |
| 8 沉淀 | **新增** task-episode；**已有** `episode-store` 纪律、`skill-library` | 任务结束 | 沉淀失败不影响任务结果，只丢经验 |
| 9 表达 | **已有** `speech-budget.js:164 request`、`:207 tick`、`:223 stats` | 15s 结算/按需 | 预算不足→沉默，结果留在记录里 |

**为什么定向是 30s、不是 1s**：1s 属于感知（已有，3.8–4.2ms/秒）；任务级决策的物理延迟是秒级，1s 重复判断只会制造抖动。
**为什么不是固定 cron**：用户作息不固定（ADR-010 同款理由），事件驱动 + 有目标时才心跳，没目标时 0 成本。
**为什么规则管「做不做」**：预算、步数、活动状态、熔断计数都是代码里的真值；让模型在提示词里数步数，等于让 AutoGPT 重演。
**为什么没有单独的「1 次/分钟」节拍**：主动开口的节流已由 `speech-budget` 的日预算 + 90s 结算承担（`:207 tick`、`:223 stats`）；
再开一个 1/min 定时器会与它打架，且「能不能说」和「该不该做」本来就是两件事（ADR-004 第 4 条）。

### 2.1 目标准入闸（防跑偏的第一道）

一个 goal 只有同时满足以下条件才允许进入 `active`：

1. `done_when` 指向一个 T2/T3 oracle（ADR-007）；前台用户发起的目标允许 `user_confirm` 兜底，
   后台/自主目标不允许——**没有可验证条件的只能当 `note`，不能自主执行**；
2. `budget`：`maxSteps`、`maxWallMs`、`maxLlmCalls` 三选二必填；
3. `risk: low|medium|high`；`high` 必须 `ask_user` 确认，`medium` 只允许可逆动作；
4. 与当前 active goal 的 intent key 不重叠（复用 `dispatch/index.js:992` 的意图去重思路）；
5. 来源是 `user` 或到期的 `open_loop`；`curiosity` 默认关，开启时只读、每小时 ≤1 次、走 speech-budget。

## 3. 四条记忆怎么落（CoALA 映射）

| CoALA | 我们叫什么 | 存哪 | 谁写 | 谁读 | 生命周期 |
|---|---|---|---|---|---|
| **Working** | 目标栈 + 当前计划 + 最近动作 | `data/goals.json`（原子写）+ `mind-kernel` 内存 + `dispatch` 的 plan 对象 | `mind-kernel` / 计划状态机 | LLM 循环（只读差分）、arbiter | 任务级；每子任务 checkpoint；重启后 active→paused |
| **Episodic** | 对话片段 + 任务叙事 | **已有** `data/episodes.jsonl`；**新增** `data/task-episodes.jsonl` | `episode-store`（已有）/ 任务结束钩子 | `memory-recall`（已有）、t=0 技能/教训检索 | 永久追加；任务叙事 90 天可归档 |
| **Semantic** | 用户事实 + 知识库 + 反思结论 | **已有** `user-facts.js`（双时态）、知识库、`insights.jsonl`（ADR-010） | `user-facts` / `reflection`（ADR-010） | `memory-recall`、目标准入 | 软失效，不删除（ADR-010） |
| **Procedural** | 技能 + 坑/教训 | **已有** `skill-library.js`（skills.json）、`pitfalls.json`；**新增** task-lesson | 技能沉淀（ADR-012）/ 失败恢复 | t=0 检索，最多 3 技能 + 3 教训 | 版本化；候选隔离；可降级/墓碑 |

**关键边界**：`world-store` **不是记忆**——它是秒级 TTL 的感知工作集，过期即失；不要把它当 semantic 或 episodic 写。
**为什么任务叙事单独一个文件**：对话 episode 回答「我们聊了什么」，task-episode 回答「这类事怎么做成的」；
混在一起会让召回既要语义又要程序，两个都做不好——对话与任务是两种检索粒度，目标不同。

### 3.1 三个新对象的形状（最小可用）

```
goal  = { id, text, source:user|open_loop|curiosity, status:queued|active|paused|done|failed|abandoned,
          done_when:OracleRef, budget:{maxSteps,maxWallMs,maxLlmCalls}, risk, plan_id, evidence[], created_at }
plan  = [{ id, text, status:todo|doing|done|failed, verify?:OracleRef }]        // ≤8 条（ADR-006）
task  = { id, goal_id, task_signature, outcome, steps_used, plan, oracle_evidence,
          what_worked|why_failed, lesson_ids[], at }                              // task-episodes.jsonl
```

## 4. 长任务评测：把 OSWorld 式判据接到 `_probe/agent-eval`

### 4.1 三个基准各自教会我们什么

- **OSWorld**：成功 = `result_getter` 读应用真实状态 → `metric(result, expected)`；多判据 `and` 串联、`or` 只在两种合法解时用；
  26/368 个 infeasible 任务要求 agent **主动 `FAIL`**，否则 0 分。→ 我们缺的正是这个「主动失败」信号与任务级 getter。
- **τ-bench**：不比对轨迹，把 gold 动作在**全新数据副本**上重放得到目标状态 hash，再与 agent 最终状态 hash 比。
  → 长任务允许「换一条路做成」；判据是**结果等价**，不是步骤一致。
- **Terminal-Bench**：`run-tests.sh` 隐藏测试 + `solution.sh` 参考解；`expert_time_estimate_min` 用来校准预算。
  → 每条 oracle 必须被 gold 解证明「正确解能过、当前错误解不过」；否则 oracle 本身就是 bug。

### 4.2 现有 harness 的映射（`_probe/agent-eval/tasks.mjs`）

| OSWorld / τ-bench | 我们现在 | 要补的纪律 |
|---|---|---|
| `instruction` | `title` / 任务描述 | 只用用户语言描述目标，不提示操作路径 |
| `config`（setup） | `setup` | 故障注入也放这里；`cleanup` 必须能撤 |
| `evaluator.result`（getter） | `verify` + `hostVerify` | **只读外部状态**；禁止 `return {ok:true}` 自证 |
| `evaluator.expected` + `func` | `hostVerify` 断言 | 多判据 and/or；别写成「包含关键字就算过」 |
| `conj` / `infeasible` | 无 | 新增 `kind` 与「主动 fail + 零副作用」判据 |
| `trajectory` | `last-run.json` | 保留每步动作+证据，供归因 |
| `expert_time_estimate_min` | 无 | 新增 `goldSteps` / `goldMs`，预算 = gold×1.5–2 |

**新增任务字段**（不破坏现有 10 条）：

```
{ id, title, kind: atomic|composite|infeasible|recovery|long,
  setup, run, verify, cleanup, hostVerify,
  oracle: { result, expected, metric, conj },     // Node 侧 getter，不调工具
  gold:   { steps: [...], ms },                    // 参考解，用于证明 oracle 可过
  inject: [{ fault: 'minimize'|'modal'|'disabled'|'uia_shell'|'lie' }],
  budget: { maxSteps, maxWallMs }, stability: high|low }
```

### 4.3 判据与指标（长任务专用）

| 类型 | 判成功的条件 | 额外硬约束 |
|---|---|---|
| composite（多步复合） | T3 oracle 全绿（and） | 步数 ≤ gold×2；`done` 必须显式发出 |
| infeasible（不可完成） | 最后动作是 `fail`，且 T3 判「目标确实不可达」 | **副作用为零**：目标文件/目录 hash、窗口集合、剪贴板前后一致 |
| recovery（故障恢复） | 注入 1 个故障后 oracle 仍绿 | 误伤计数 = 0；恢复步数 ≤5；每上一档有 evidence |
| long（≥8 步） | T3 oracle 绿 + 子任务 T2 全绿 | 步数 ≤ gold×1.5；墙钟 ≤ gold×2；两次重规划内完成 |
| liar（谎报注入） | **oracle 必须判失败**（这条测 oracle，不测 agent） | 5/5 失败才算 oracle 合格 |
| grounding 探针 | 指到的元素在目标 bbox 内 | 不真点，成本 ≈ 一次视觉调用 |

**统一指标**：`success_rate`、`avg_steps`、`p50/p95`、`recovery_rate`、`collateral_count`（必须 0）、
`oracle_false_positive`（liar 下必须 0）、`plan_adherence`（动作能否映射到计划条目，不能则停止）。

### 4.4 怎么跑 LLM 级长任务（不改产品代码）

- **外部同构（现在就能做）**：runner 自己读 `llm_providers.json`，用同一条 prompt + 同一套工具 schema 调模型，
  工具仍走 `executeTool`。结论标注「同构复现」，**不宣称测到了宿主真实链路**（缺易变尾巴注入与插件 hooks）。
- **宿主入口（产品改动，另开）**：`POST /agent-run {task, budget}` 返回轨迹（ADR-006 Action Item 6）。
  有了它，长任务评测才真正测到 `mind-kernel + plan-store + LLMHandler`。

**为什么先做 liar**：如果 oracle 抓不住「工具说做了但没做」，后面所有长任务分数都是假的；
这一条不过，不允许开始长任务评测（与 `复盘-真假成功` 同一结论）。
