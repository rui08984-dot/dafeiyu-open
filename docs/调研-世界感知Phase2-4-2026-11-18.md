# 世界感知 Phase 2–4 调研与设计（2026-11-18）

> 主交付。上游约束来自 `docs/adr/ADR-004-世界感知与推理成本.md` 与 `docs/架构总览-2026-11-17.md`：
> **>5ms 的推理不进帧循环；世界状态只进易变尾巴、绝不进 system；云端 VLM ≤6 次/小时；本地 Ollama 仅 `free_mb≥6000`。**
> 本文所有外部结论都带 repo+路径或论文号；没核到的进末尾「未核实」，不猜。

**结论摘要**

1. Phase 2 最划算的是**浏览器标签页**（0 LLM、1 个本地 POST、信息密度最高）；**通知**受 Windows 打包身份硬约束，建议默认不做。
2. RSS 必须**批量抓取 + 本地去重 + 一天一次简报**；去重抄 MinHash LSH，不抄「每条摘要」。
3. 记忆 v2 的反思触发器抄 Generative Agents 的**重要性累加器**，巩固策略抄 Graphiti 的**软失效（valid_at/invalid_at）+ 增量摘要水位线**；我们已有的 `user-facts` 双时态正好接得上。
4. Phase 4 不需要从零建：`speech-budget` 已经有 `accepted/ignored/negative` 与 90s 结算窗口（`js/core/speech-budget.js:187,207,223`），补的是**上下文归因**与**活动标签夹具**。
5. 最该否掉：持续抓选中文本/剪贴板正文；直接读 `wpndatabase.db` 绕通知 API。

配套 ADR：ADR-005（浏览器/通知源接入）、ADR-009（信息流与今日简报）、ADR-010（记忆 v2 反思/巩固）。

## 2. Phase 2：更多信息源

### 2.1 浏览器标签页（先做这个）

**架构（为什么不是 native messaging）**：扩展 → `POST http://127.0.0.1:8103/world/browser`，带 `X-World-Token`。
native messaging 要写注册表 + host manifest + 每浏览器装一次，换机器就重来；本地 HTTP 我们已有（8004/8103），
但**现在的 8103 是 `Access-Control-Allow-Origin: *` 且无鉴权**（`petbridge/vts-server.mjs:367-369`），
任何本机进程都能 `POST /say`——新增入口必须带 token，且只做**只读事实**，不复用 `/say`。

**数据模型**（`web.tab` 一个事实，字段刻意比 AW 窄）：

```
{ ts, site:"bilibili.com", title:"...", audible:false, incognito:false, tabCount:7 }
```

- 只存 **origin（scheme+host）**，默认不存 path/query：搜索词、视频 id、邮箱 uid 都在 path/query 里，收益低、泄露高。
- 白名单站点（用户显式勾选，如 bilibili/youtube）才存 path 的**首段**，用于区分「首页/视频」。
- `title` 单独限长 80 字；对 denylist 域（mail/bank/health/内网）**连 title 都不存**，只记 `site`。
- `incognito=true` 时只记 `{incognito:true}`，其余全丢（aw-watcher-web 也是把 incognito 作为字段上报，`heartbeat.ts:90`）。

**采样与去重**：`tabs.onActivated` / `onUpdated`（只看 url/title/audible 变化）+ 60s alarm 心跳；
相同 payload 用 `deepEqual` 跳过（`aw-watcher-web/src/background/heartbeat.ts:109`）；
发送前 800ms 防抖，避免 SPA 改标题导致连环 POST。MV3 SW 会被挂起，保活抄 `offscreen.ts` 的 20s 消息（仅 Chrome）。

**写进 WorldStore**：`web.site` / `web.title` / `web.audible` / `web.incognito`，TTL 120s（浏览器切换不像前台窗口那么频繁，
但也不能太长）；`source:'browser'`，`sourceRank` 75（低于 system 90，高于 hint 60）。
活动状态 hint：白名单视频站 + `audible` → `hints.screenState='video'`（只作为弱信号，不抢全屏+媒体的强判据）。

**注入**：只在变化时写 `站点=bilibili.com；页面=《…》`，≤20 tokens；`incognito` 只写「浏览器=隐私窗口」。
**不做**：常驻 content script 抓 DOM、抓 selection。

**成本**：0 次 LLM；每次事件 = 一次本地 HTTP 往返（ADR-004 记的「HTTP 数 ms」，与 8103 现有控制口同量级）；默认不落盘（事实在内存，TTL 到期即失）。
可选 `browser_history_days:7` 才写 JSONL，单条 ≤300B，7 天 ≤2MB。

### 2.2 Windows 通知（默认不做，做成可选模块）

**硬约束（已核）**：MS Learn「Notification listener」明确「must add the User Notification Listener capability to your app manifest」；
`RequestAccessAsync` 必须在 UI 线程调用，用户拒绝后只能去系统设置改。
我们当前是 **electron-builder + squirrel 的非打包应用**（`_incoming/my-neuro/live-2d/scripts/electron-ui-package/package.json:6`，入口 `大肥鱼.cmd`），
没有 package identity，**直接调会失败**。本轮 GitHub code search 也未找到专门的开源监听器封装
（命中的都是同名无关类），能用的只有 `pywinrt` 投影 + 官方 delta 示例。

**四条路对比**：

| 方案 | 能否用 | 代价 | 结论 |
|---|---|---|---|
| 稀疏 MSIX（external location）给 helper 身份 | 能，官方文档支持 | MinVersion 19041；`AllowExternalContent=true`；`runFullTrust`+`unvirtualizedResources`；证书必须被信任；安装器要注册/卸载 | **可选模块**，Phase 2.5 |
| UIA 轮询通知中心 | 能但脆 | 要窗口可见/展开，UI 改版就挂，采样 >5ms | 否 |
| 读 `%LOCALAPPDATA%\...\wpndatabase.db` | 未核实，极可能 ACL 拒绝 | 无文档、随版本变、行为像恶意软件 | **否**（见 §7-7） |
| 不做 | — | 少一个高敏感源 | MVP 默认 |

**若做**：独立 `pet-notify.exe`（Rust 或 C#）带稀疏包身份，`NotificationChanged` 事件 → `GetNotificationsAsync` 求差集
（官方示例的 delta 算法）；只上报 `{app, title, at, count}`，**正文默认不读**；按应用 allowlist（默认只日历/邮件）；
TTL 10 分钟；进世界行只写「刚收到 3 条通知（微信）」这种聚合，不写正文。
**成本**：2–4 天打包/证书/安装器 + 1 个常驻进程（~10MB）；收益是「她知道我刚被什么打断」，但敏感度最高。

### 2.3 RSS/Atom + 今日简报

**抓取**：≤30 个源，20 分钟一轮，串行 + 8s 超时 + 200KB/源上限；带 `If-None-Match`/`If-Modified-Since`（304 不解析）。
解析用 `rss-parser` 的 `parseURL`（`lib/parser.js:73`），拿 `title/link/isoDate/contentSnippet/guid`。
**网络出口必须走主进程或 Python 服务**，不让渲染层直接 fetch 外网（CSP + 出口可审计）。

**去重三层**（顺序执行，越后越贵）：
1. 精确：`guid` 或规范化 `link` 的 SHA-1；
2. 跨源近重复：标题+摘要做 3-gram shingle，MinHash LSH `threshold=0.85, num_perm=64`（`datasketch/lsh.py:51`），
   命中的进同一 cluster，保留最早一条；
3. 同源重复：同一 feed 内标题 Jaccard ≥0.9 直接丢。
> 不用 SimHash：条目量级是每天几百，MinHash LSH 足够；SimHash（Manku 2007）是为亿级网页设计的。

**显著性排序（0 LLM）**：`score = 0.45*recency(24h 半衰) + 0.25*sourceWeight + 0.20*interestMatch + 0.10*clusterSize`；
`interestMatch` 用 `user-facts` 的关键词/实体命中；最后用 MMR（λ=0.7）去冗余，保证前 12 条不都是同一事件。
**今日简报**：每天**一次**，在 08:00 后第一次 `idle≥10min` 时触发；输入 top 12 条（标题+一行摘要，≤1200 tokens），
输出 ≤200 tokens 的「今天值得看」；存 `data/今日简报.jsonl`。
**注入**：不主动塞进每轮；用户问「今天有什么」时读；或作为一次低优先级 offer 走 `speech-coordinator`（受 `speech-budget` 约束）。
**成本**：采集 0 LLM；简报 1 次/天（~1.2k in / 200 out）。**禁止**逐条摘要（违反 ADR-004 的批量纪律）。

## 3. Phase 3：记忆 v2

现有地基（不要重造）：`user-facts.js` 已有 `valid_from/valid_to/supersedes/superseded_by`（`js/core/user-facts.js:159-170`）；
`episode-store.js` 已有空闲巩固与游标；`memory-evolve` 已有规则门控 + 8090 嵌入去重 + 每 6 轮巩固。

### 3.1 反思/巩固（把零散事实压成结论）

**触发（抄 GA 的累加器，不按固定时间）**：
- 每条新事实/片段给 `importance ∈ 1..10`：规则权重（复用 `memory-evolve` 的 RULES 权重） + 新颖度（与已有事实的最大余弦距离）；
- `acc += importance`；当 `acc ≥ 60` 且新增条目 ≥6 且 `idle ≥10min` → 跑一次反思；每天 ≤4 次，且两次间隔 ≥1h；
- 额外触发点：episode 卡片生成后（等价 Letta 的 compaction-event，`memory-reminder.ts:51`）。
**为什么不是「每晚 3 点」**：用户作息不固定，固定时刻经常人在打游戏；累加器保证「值得想的时候才想」。

**输出**（`data/insights.jsonl`，追加，不改写原文）：

```
{ id, text:"他最近连续三晚在 23 点后打游戏，白天提到过睡眠不足",
  kind:"pattern|preference|relationship|open_loop",
  evidence_ids:["f...","e..."], confidence:0.65,
  valid_from, valid_to:null, superseded_by:null, created_at }
```

- **证据链硬约束**：`evidence_ids.length ≥2` 才允许落盘（GA 的 insights+evidence，`reflect.py:38`）；不足就丢弃。
- 去重：与已有 insight 余弦 ≥0.88 → 合并（保留证据并集）；矛盾 → 复用 `memory-recall` 的 `_adjudicateFact` 小 LLM 裁决；
- 沉淀：高置信（≥0.75）且稳定的 insight 才写入 `user-facts`，`source:'reflection'`，置信度封顶 0.7（反思永远低于用户明说），**不删除旧事实，只 supersede**。

### 3.2 开放回路（未完成的承诺/待办）

```
{ id, kind:"promise|todo|question", text:"他说周末要给我看新做的曲子",
  due_hint:"周末", status:"open|done|dropped", evidence_ids:[...],
  created_at, closed_at, last_nudged_at, nudge_count }
```
- **抽取**：规则优先（「我待会/等下/明天/周末…」「记得提醒我…」「回头…」），命中才在**该 episode 卡片生成时**顺带做一次 LLM 抽取（不额外加调用）；
- **闭环**：显式（「做完了/算了/不弄了」）→ done/dropped；隐式（相关事实被 supersede）→ done；TTL 7 天 → 问一次再 dropped；
- **提醒**：每个回路每天最多 1 次，只在 `working/idle` 且 `speech-budget` 放行时说；`gaming/watching/away` 一律不打扰。

### 3.3 关系时间线

不建图、不建新库：`timeline.js` 是**纯函数视图**，输入 `user-facts`（valid_from/to）+ `episodes.jsonl`（日期+标题），
输出按月分组的事件列表。只在用户问「之前/上次/我们」时注入 ≤60 tokens；平时不注入。
**为什么不做图数据库**：单机几十条事实，JSON + 原子写足够（与 `user-facts` 同一判断）；图库的代价是启动/迁移/备份三份复杂度。

### 3.4 与现有模块的接口

| 模块 | 读 | 写 | 频率 | LLM |
|---|---|---|---|---|
| `world-sense` | world-store 事实 | 易变尾巴 | 每轮 | 0 |
| `memory-evolve`（现有） | 对话 | MemOS | 每 6 轮 | 0 |
| `reflection`（新） | user-facts + episodes + insights | insights.jsonl、user-facts | 触发式 | 1 次/反思 |
| `open-loops`（新） | episode 卡片 + 对话事件 | open-loops.jsonl | 每 episode | 0（搭车） |
| `memory-recall`（现有） | 以上全部 | 易变尾巴 | 每轮 | 0（裁决时偶发） |

**MemOS 的边界**：它仍是原文/语义检索库（8003，`memory-evolve` 写入）；reflection **不回写 MemOS**——
同一结论若在 MemOS 与 `insights.jsonl` 各存一份，召回时会出现两个版本、无法判定谁更新。结论只走 `insights → user-facts`，原文留在 MemOS。

## 4. Phase 4：感知评测（要能跑、能出数）

### 4.1 活动状态准确率

**没有公开 ground truth**：ActivityWatch 的 `aw-core`/watcher 子仓 grep `ground truth|accuracy|evaluat` 只命中一处隐私规则说明，无标注/评测代码；
公开可用的活动识别数据集多为传感器或视频动作，本轮未找到「working/gaming/watching/idle/away」五态标注集（arXiv/Semantic Scholar 被限流，未穷举）。**必须自建小样本**。

- **标注夹具**：`POST /world/label {state}` + 全局热键，把「当前 snapshot + 人给的标签」写 `_probe/out/world-labels.jsonl`；
  每个状态 ≥10 条、总计 ≥50 条（约 3 天自然产生）。
- **离线回放**：`world-store.classifyActivity` 是纯函数，把标注里的 snapshot 重放 → 混淆矩阵、每状态 P/R/F1；
  **macro-F1 ≥0.75** 为通过。回放不依赖宿主，可进 `check-all --fast`。
- **在线稳定性**：`history` 里 5 分钟内状态翻转次数 >3 记一次「抖动」；目标 **≤6 次/小时**（误判通常表现为抖）。

### 4.2 打扰有用率

**大部分已有**：`speech-budget.record(attemptId, outcome)` 记 `accepted/ignored/negative`，
`tick()` 每 15s 用 90s 窗口结算（`js/core/speech-budget.js:187,207`），`stats()` 已输出 `accept_rate` 与 `annoy_index`（`:223`）。
**补的是归因**：`request()` 时把当时的 world snapshot 摘要挂到 attempt 上，落 `proactive-ledger.jsonl`；
指标：`accept_rate ≥0.35`、`ignored ≤0.55`、`negative ≤0.08`，并按 `activity` 分组（游戏中被忽略是预期的，工作时段不该）。
**为什么不用「她说了几句」当指标**：说的多不等于有用；负反馈权重必须高于忽略。

### 4.3 记忆召回率

- **本地金集**：从 `user-facts` 抽 30 条（覆盖换猫名/搬家/偏好/时间点），人工写问题；
  `recall_any@5 ≥0.85`，且 **stale-leak=0**（注入里出现 `valid_to` 非空的事实即失败）。
- **标准化回归**：LongMemEval 抽 50 题跑我们的召回管线，用它的 `recall_any/recall_all/ndcg@10`（`eval_utils.py:24`）；
  只作为**版本回归**（这次改动不许比上次低 3 个点），不对外宣称绝对能力。
- **反思质量**：证据覆盖率 100%（无 evidence 的 insight 不允许存在）；上线 1 个月后人工抽查 20 条，矛盾率 ≤5%。

### 4.4 门禁接线
