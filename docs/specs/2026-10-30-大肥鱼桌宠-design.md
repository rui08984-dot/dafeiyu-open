## 1. 一句话

在桌面上养一个**数字同事**：它有大肥鱼的脸和声音，情绪和动作跟着 DSH 的工作状态走，带着 AstrBot 那套人格与记忆，能把你说的话变成 DSH 里的任务。

## 2. 第一性原理重建

### 2.1 claimed_constraints（被当作固定的限制）

| 声称的约束 | 分类 | 裁决 |
|---|---|---|
| 必须接进 DSH | **惯例/偏好** | 保留为"当前唯一数据源"，但必须经过一层 `AgentBridge` 抽象（未来换 Codex/别的才不返工） |
| 必须用 Live2D | 偏好 + 授权 | 保留。资产已买/已下，且是"有张会动的脸"最省的路 |
| 必须自己训 TTS / 克隆音色 | 惯例 | **丢弃**。edge-tts 足以满足"它在跟我说话" |
| 必须是独立窗口 | 真实需求（陪伴感） | 保留，但它同时要求"不挡操作"和"能拖" → 这是外壳的硬指标 |
| 要有记忆和人格 | 真实需求 | 保留，但**分两期**：先身体，后灵魂 |
| 要能派活给 Agent | 真实需求 | 保留，二期。它是"效率价值"，与"陪伴价值"验收标准完全不同 |
| 不设期限 | 项目管理偏好 | 不改变架构，但要求**每周有可见进展**，否则永远做不完 |
| 只自己用 | **真实约束**（最省事的一条） | 决定：模型不入库、不分发、Cubism Expandable 条款完全不用管 |

### 2.2 primitives（可独立支撑的基本事实）

1. 屏幕上需要一个**持续存在、透明、不挡点击**的窗口 → OS 能力，Electron/Tauri 都提供。
2. Live2D 模型必须 **WebGL** 渲染，且这只模型是 **moc3 v5 → 必须 Cubism Core 5.x**（已实测）。
3. 口型只能由**真实音频包络**驱动（RMS），按字数估是假的。
4. 状态源是 DSH 的 `session/event`，可折成 6 档（已验证）。
5. 说话需要 TTS；本机 edge-tts 已在跑，**不需要 GPU**。
6. 记忆需要持久化；SQLite + FTS 在个人规模下足够，**不需要向量库**。
7. 三个进程之间只需要本机 `127.0.0.1` 的 HTTP/WS。

### 2.3 discarded_assumptions（被丢弃的惯例）

- ~~需要自己设计 UI~~ → 直接抄现成（你已明确要求）。
- ~~需要独立设计一套插件框架~~ → DSH 已有插件机制，我们只写薄插件。
- ~~需要 GPU / 本地大模型~~ → edge-tts + 软渲染即可；只有"本地 TTS 克隆/ASR"才要。
- ~~需要一次做完~~ → 拆 M0–M6，每个里程碑独立可验收。
- ~~Live2D 是唯一路线~~ → 已持有资产，不再评估替代方案（VRM/Inochi2D 仅在将来换形象时再议）。

### 2.4 rebuild（只用基本事实推出来的最简方案）

**三个进程 + 两个协议 + 一个存储：**

`@
宠物壳 (Electron)          ← 透明置顶窗 / Live2D 渲染 / 音频播放 / 气泡字幕
   │  pet.state  (HTTP/WS, DSH→宠物)
   │  pet.intent (CLI 或 HTTP, 宠物→DSH)
桥插件 (DSH bundle)        ← session/event → 6 档状态 + 台词 + 审批提醒
人格服务 (宠物壳内嵌起步)  ← 人格 prompt + SQLite 记忆 + 主动性调度
`@

- 不写"框架"，只写**三块**：窗口、桥、脑子。
- 桥插件薄到可以扔（< 500 行），DSH 升级坏了也不心疼。
- 人格先跑在宠物壳里（一个进程），**只有需要独立常驻/多客户端时才拆出去**。

### 2.5 binding_residuals（仍然存在的真实限制）

- Cubism Core 是专有软件（只自用则无碍）。
- 大肥鱼模型**不可再分发**（作者明令）。
- DSH 本版**没有 TTS**、ASR 只有实验包。
- moc3 v5 + pixi-live2d-display 有遮罩瑕疵（用 `hiddenParts:["Part46"]` 规避）。

### 2.6 kill_test（最便宜的证伪）

> **用 300 行以内的代码，让 DSH 页面里出现一只会呼吸的大肥鱼，并在 `turn/start → turn/end` 时换一次表情。**
> 这一步做不到，后面全部作废——这就是 **M0**，一天内必须有答案。

## 3. 架构（三层）

`@
┌──────────────────────── 宠物壳 (Electron, 独立常驻) ────────────────────────┐
│  透明无边框置顶窗 · 点击穿透(仅宠物实体区域接收) · 拖动 · 托盘             │
│  ┌─────────────┐  ┌──────────────┐  ┌───────────────┐                    │
│  │ Live2D 渲染 │  │ 气泡/字幕层   │  │ 人格与记忆服务 │                    │
│  │ Core5+pixi  │  │ 单槽优先级    │  │ SQLite + 调度  │                    │
│  └─────────────┘  └──────────────┘  └───────────────┘                    │
│         ▲               ▲                    │                            │
│         └──── RMS 包络 ─┘                    │ pet.intent (任务)          │
└──────────────────────────────────────────────┼────────────────────────────┘
                    ▲ pet.state (6档+文本)     │
┌───────────────────┴──────────────────────────▼────────────────────────────┐
│                       桥插件 @local/dsh-pet-bridge                        │
│   ctx.on('session/event') → 6 档聚合 → 推给宠物                            │
│   ctx.webServer.register('/pet/state')  /  接收 intent → dsh CLI 派活      │
└───────────────────────────────────────────────────────────────────────────┘
                                   │
                              DSH 会话 / 任务
`@

**数据流**
1. DSH 跑任务 → `session/event` → 桥插件折叠成 6 档 + 一句台词 → 推给宠物壳 → 表情/动作切换。
2. 你说话（或打字）→ 宠物壳 → TTS 合成 → 播放 → 同时把 mp3 解码成 RMS 包络 → 驱动 `ParamMouthOpenY`。
3. 你说"帮我跑个测试" → 宠物壳判定是任务 → 任务卡 → 你确认 → `dsh` CLI 起一个会话 → 后续同 1。

**错误处理**
- 桥插件连不上 → 宠物回"离线段子"（本地随机语料），不报错、不退出。
- TTS 失败 → 降级为字幕，口型归零。
- Cubism 加载失败 → 显示静态立绘 + 一行错误气泡（不要白屏）。
- 模型部件异常 → `hiddenParts` 兜底。

| | A：改 GHOST CE | **B：自研三层（推荐）** | C：抄 AAAAGENT 整机 |

## 6. 已确认的 7 项架构决策（2026-10-30）

| # | 决策 | 结论 | 备注 |
|---|---|---|---|
| 1 | 窗口外壳 | **Electron**（不复用 Coopanion 壳） | 用户明确"不要 coo，不关它的事"；现有参考全是 Electron |
| 2 | 生命周期 | **宠物独立常驻**，DSH 只是数据源 | DSH 不在线时进入"离线人格"模式 |
| 3 | AstrBot 复用 | **抄机制自研** | 无 AGPL 传染，存储用 SQLite+FTS5，不引入向量库 |
| 4 | 语音输入 | **M6 才做**，faster-whisper | 先做"它说"，再做"你说" |
| 5 | 派活形态 | **任务卡确认后执行** | 不会误触发改库 |
| 6 | UI 来源 | **由我组合最优**：dsh-pet（气泡/设置/穿透）+ GHOST（渲染/口型）+ AAAAGENT（任务卡/记忆页）+ Artemis（桥语义/行为引擎）+ AstrBot（人格机制） | 不做原创设计 |
| 7 | 窗口尺寸 | **420 × 525（4:5）** | 按模型构图定，尺寸算 UI 的一部分 |

> 结论：**M0 探针是唯一的先行项**。它不通过，后面全部作废。

## 7. ADR 草稿

### ADR-001：桌宠外壳采用 Electron
**Status:** Proposed ｜ **Deciders:** 你
**Context:** 需要透明、置顶、点击穿透、可拖动的常驻窗口；现有可抄代码（dsh-pet、GHOST、Coopanion）全是 Electron/TS。
**Options:** Electron（TS 全栈，复用率最高，包体 ~100MB）｜ Tauri（5MB，但要 Rust）｜ 复用 Coopanion 壳（耦合）。
**Decision:** Electron。
**Consequences:** 包大、内存高；但零学习成本、代码可直接抄、与 DSH 插件同语言。

### ADR-002：宠物独立常驻，DSH 作为数据源
**Status:** Proposed
**Context:** 陪伴价值要求"它一直在"，而 DSH 会被关掉/重启。
**Options:** DSH 拉起宠物（简单，生命周期单一）｜ 宠物常驻 + 桥插件推送（解耦，需处理 DSH 不在线）｜ 双模式。
**Decision:** 宠物常驻；DSH 不在线时进入"离线人格"模式，用本地语料与记忆自说自话。
**Consequences:** 需要一个看护/单实例机制；换来的是一直在。

### ADR-003：人格与记忆抄 AstrBot 机制自研
**Status:** Proposed
**Context:** AstrBot 的 livingmemory / proactive_chat 是成熟设计，但 AGPL + Python + IM 中心。
**Options:** 跨进程接服务（快）｜ 抄机制重写（干净）｜ 只用人格文件。
**Decision:** 抄机制重写，存储用 SQLite + FTS5，不引入向量库。
**Consequences:** 多花 3–5 天；换来无 AGPL 传染、无跨语言调试。

### ADR-004：TTS 采用本机 edge-tts
**Status:** Proposed
**Context:** DSH 本版无 TTS；GPU 不可依赖；已有 edge-tts 服务。
**Options:** edge-tts（零成本，需联网）｜ 云 TTS（稳，按字计费）｜ VoxCPM/GPT-SoVITS（要 GPU）。
**Decision:** edge-tts，播放走 WebAudio，同时取 RMS 驱动口型。
**Consequences:** 离线不可用；音色可选范围受微软限制。

### ADR-005：任务派发必须经过用户确认
**Status:** Proposed
**Context:** 宠物误听会把错误指令变成真实代码改动。
**Options:** 直接派（快）｜ 任务卡确认（安全）｜ 只能在 DSH 里派。
**Decision:** 任务卡确认；卡内含目标、目录、预估动作，可编辑后确认。
**Consequences:** 多一步交互；换来不会"它自己把库改了"。

## 8. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| DSH 插件 API 变动 | 桥插件失效 | 桥保持 <500 行；锁定 `dsh.compatibility.dshReleases` |
| moc3 v5 渲染瑕疵 | 视觉 | `hiddenParts`；必要时换 Core 版本组合复验 |
| 透明窗点击穿透在不同 DPI/多屏失效 | 体验 | 抄 dsh-dafeiyu 的跨显示器拖动与穿透实现 |
| edge-tts 接口变动 | 不能说话 | 抽象 `TtsProvider`，可切云 TTS |
| 记忆无限膨胀 | 变慢 | 分层：原始对话 N 天 → 摘要 → 长期事实；定期巩固与遗忘 |
