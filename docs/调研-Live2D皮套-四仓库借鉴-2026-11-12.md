### 2.2 血缘证明：它用的就是我们这份模型

它的 `core-inventory.json` 是从模型 moc3 导出的参数清单（`coreVersion 83951616`）。拿它和我们的 `pet.cdi3.json` 做集合比对：

```python

ours   = json.load(open(r'<project-root>/pet-runtime/desktop/assets/jellyfish/pet.cdi3.json', encoding='utf-8'))
theirs = json.load(open(r'<project-root>/_research/jingyu/core-inventory.json', encoding='utf-8'))
mine   = {p['Id'] for p in ours['Parameters']}
theirs_ids = {p['id'] for p in theirs['parameters']}
print(len(mine), len(theirs_ids), len(mine & theirs_ids))
```

输出：

```
509 509 509
```

即 **509 个参数 ID 完全一致，双方都没有多余项**。辅助证据：

| part 数 | 147 | 148（重打包多 1 个，差异见 §8 注） |

### 2.3 它是干什么的

```
自然语言 ──► LLM/DSH 出「语义动作计划」(JSON) ──► compiler 硬校验 ──► 参数轨道 ──► 8 级管线演出
                 │                                     │
                 └── 只上传文本 + 能力目录              └── 范围/时序/冲突/物理所有权
```

三种执行后端：网页舞台（自研）、VTube Studio（编译成 VTS 原生动作热部署，保留作者物理）、导出 GIF/MP4（含 Spout2 原生帧流）。外壳还有：透明网页桌宠（Electron）、直播间（OBS/镜头/冷热场）、Minecraft 试验场、面捕 MCP。

#### ② 编译器（`compiler.py`，294 行）

输入语义 IR，输出参数轨道。支持 10 种动作：

```python
'trajectory'  # 2..60 帧连续多轴，帧间隔 ≥0.08s，距首尾 ≥0.15s，每帧 1..12 个语义输入
'look'        # left/right/up/down/center；眼先动，头延迟 ≤0.09s，身体延迟 ≤0.19s
'nod' / 'shake_head'  # 1..4 次，波浪曲线，带预备动作
'tilt'        # left/right，身体反向平衡
'smile'       # ParamMouthForm + EyeSmile + MouthSmile_L/R 一起
'blink'       # both/left/right，1..4 次
'expression'  # exp3 名字；layer = exclusive | overlay；0.2..59 秒
'gesture'     # hand_on_chest / point / grass；可 pair；关节 accents 0..12 段；armBinding guided|off
'talk'        # 仅口型节奏，不生成音频
'pose'        # 1..12 个语义输入直接给值
# 另有 'recorded'（社区手调录制 2..1200 采样点）
```

关键机制（这是最值得抄的部分）：

```python
def add(pid, start, duration, points, index, label, expression=None):
    if pid not in PARAMS: raise CompileError(f'模型没有参数 {pid}')
    if pid in PHYSICS_OUTPUTS: raise CompileError(f'{pid} 归作者物理控制，不能直接驱动')
    ...
    for old in tracks:                      # 通道冲突：硬报错，不靠运行时覆盖
        if old['id']==pid and overlap(old, new) > 0.015:
            if not (bool(expression) != bool(old.get('expression'))
                    and overlay.get('layer')=='overlay'
                    and pid in PRIMARY and base_kind!='gesture'):
                raise CompileError(f'动作 {old["action"]+1} 与 {index+1} 同时控制 {pid} ...')
```

- 每条轨道首尾自动补 `PARAMS[pid]['default']` → **"演完回正"是编译期保证**
- 值全部 clamp 到模型 min/max，越界进 `warnings`（不静默）
- 手势时长不足 `enter + exit + 0.35s` 时自动延长（保留作者的进入/收回动作）
- 输出 `policy: {returnToIdle: True, physics: 'author-131-rigs', easing: 'smoothstep', parameterLimits: 'moc3-core'}`

#### ③ 播放管线（`web/engine.mjs`，165 行）

每帧一张 **target map** + 8 级有序 stage：

```js
this.pipeline = new DriverPipeline()
  .add('idle',       10, c => this.applyIdle(c))         // 呼吸 sin + 作者 IDLE 曲线 + 随机待机事件
  .add('gaze',       20, c => this.applyGaze(c))         // 眼 τ=.09s，头 τ=.32s（眼先头后）
  .add('speech',     25, c => this.applySpeech(c))       // 说话姿态（来自 speech-performance.mjs）
  .add('attention',  27, c => this.applyAttention(c))    // "注意某处"的加权混合
  .add('motion',     30, c => this.applyMotion(c))       // 编译好的轨道
  .add('blink',      40, c => this.applyBlink(c))        // 只写没被 explicit 占用的眼睛参数
  .add('expression', 50, c => this.applyExpressions(c))  // exp3 当轨道：Add/Multiply/Overwrite × 权重曲线
  .add('commit',     60, c => this.commit(c));           // 逐参数一阶低通后写引擎
```

`commit` 是全局唯一出口，也是"流畅"的真正来源：

```js
for (const [id, v] of target) {
  const p = this.params.get(id); if (!p) continue;
  const prev = this.current.get(id) ?? p.default;
  const tau = id.includes('Eye') && id.includes('Open') ? .016 : .055;
  const value = clamp(prev + (v - prev) * (1 - Math.exp(-dt / tau)), p.min, p.max);
  this.current.set(id, value); this.core.setParameterValueById(id, value);
}
```

因为低通一直在，**轨道播完不需要写淡出**：目标回到 default，值自己滑回去。

`applyMotion` 里还有两条细节：
- `amplitude` 缩放只作用于非 gesture / 非 expression / 非 blink（这三类不缩，避免手势走形）
- 轨道只在 `[0, duration]` 内写，之外该参数落回 default

#### ⑦ 渲染质量（`patch_renderer.py`，122 行）

MIT 的"补丁脚本"思路值得学：对 pinned 的 Cubism vendor 做**可复现、带前后 SHA-256 清单**的两处补丁：

1. **per-drawable multiply/screen 颜色**（把 Cubism 5-r.1 的 `u_multiplyColor/u_screenColor` 回移到旧 vendor）——用于局部染色/光影。
2. **clipping mask 256 → 2048**（原 vendor 硬编码 `this._clippingMaskBufferSize=256`，角色 800×1600 时一个 mask 纹素覆盖 3~6 像素，被裙子挡住的尾巴边缘出现阶梯状锯齿；MSAA/纹理过滤都救不了）。

> 注：我们 `cubism-renderer.mjs:175` 已经调用 `setClippingMaskBufferSize(maskConfig.size)`，这块不吃亏；per-drawable 颜色我们没有，但不是当前痛点。

### 2.6 能借 / 不借

**借架构（自己用 JS 重写）**

### 3.3 核心设计（可直接借的四件事）

**① 连续情绪 VAD**（`engine/src/emotion/EmotionStateController.ts`，279 行）

```ts
interface EmotionPersonality {
  baseline?: Partial<VADVector>;
  reactivity?: number;        // 反应强度
  targetApproachRate?: number;// 逼近速度
  decayRate?: number;         // 回落速度
  emotionHoldSeconds?: number;// 保持期
  emotionBias?: Partial<Record<string, number>>;
  ambientDriftStrength?: number; // 环境漂移
}
```

- 三层：`current`（指数逼近 `target`）、`target`（被 `nudge` 推开，hold 结束后回 baseline）、`ambient`（±0.034 的随机游走）
- `nudge()` 的推量是 `0.28 + intensity*0.58`，**弱刺激也推得动、强刺激不一步推满**
- 主导情绪：先按规则切（高唤醒+低支配=慌、正效价+低支配=害羞），再取最近锚点；幅度 <0.075 只报 `soft-*` 底色
- 全部随机走 seeded RNG（同 seed 可复现）

**② FACS 语义层**（`engine/src/facs/FACSLikeState.ts`，23 个通道）

```
browInnerUp / browOuterUp / browDown / eyeOpen / eyeSmile / eyeSquint / eyeBlinkL/R
mouthSmile / mouthFrown / mouthOpen / mouthPucker
gazeX/Y / headX/Y/Z / bodyX/Y/Z / blush / tear / sweat / breath
```

它是"情绪"和"模型参数"之间的稳定中间层：换模型只改 profile，不动情绪逻辑。

**③ 分层混合规则**（`engine/src/mixer/MotionMixer.ts` + `PriorityRules.ts`）

```ts
additiveFACSKeys = headX/Y/Z, bodyX/Y/Z, breath, eyeBlinkL/R
maxFACSKeys      = mouthOpen, blush, tear, sweat
层序：idle → emotion → reaction → speech → speechPerformance → manual
```
每层每通道有独立规则（add / max / set），所以"微笑 + 微笑"不会变咧嘴。

**④ 模型画像 + 能力降级**（`engine/src/profile/`）

```ts
interface ModelCapabilities {
  headControl, bodyControl, eyeBlink, eyeSmile, gazeControl,
  mouthOpen, mouthSmile, browControl, blush, tear, sweat, breath
}
```
`CapabilityDetector` 从 `parameterMap` 推出能力；`AdaptationCoverage` / `FallbackStrategy` 在缺参数时降级；`profile-generator` 扫描模型目录直接生成 `soullink.profile.json`。

另外还有：`EmotionArchetypeRegistry.ts`（453 行，情绪 → FACS 区间 + 变体，如 `soft_smile` / `bright_smile` / `shy_happy` / `startled` / `annoyed`）、`ExpressionTimeline.ts`（关键帧 + easing）、`IdleActionScheduler.ts`（599 行，7 种待机小动作，按能力可用性筛选）、`SpeechPerformancePlanner`（说话时眉眼重点，不抢嘴）。

```ts
type EmotionSubject = 'user' | 'companion';           // 用户情绪 / 她的心情 分开存
interface EmotionObservation {
  subject, label, intensity: number|null, confidence, provenance:
    'user_explicit'|'text_recent_context'|'audio'|'video'|'companion_inference',
```

### 5.3 唯一真正值得我们拿的：音乐口型包络

问题：音乐带伴奏时，实时 RMS 跟的是鼓点，不是人声，口型会乱。
解法（`docs`/README）：先用配套工具做**人声分离**，生成与音频同名同目录的 `晴天.mp3` ↔ `晴天.vocals.env`；播放时按包络驱动口型；没有包络才退化到实时 RMS。

```js
// mouth-env.js
const MAGIC = "TSUMUENV";  // 8B
// header: magic(8) + version(4) + rateHz(4) + count(4) + refRms(4) + peakRms(4) + pad(4) = 32B
// 之后 count 个 Float32 RMS
function levelAt(env, seconds) {
  const i = Math.floor(seconds * env.rateHz);
  const r = env.rms[i] / (env.refRms > 1e-6 ? env.refRms : 0.22);
  return Math.min(1, Math.pow(Math.min(1, r), 0.7));
}
```

适用性：**只有我们做"一起听歌/ASMR"时才需要**。做的话照这个格式存包络最省事（47 行解析器）。

第二个可借的小东西：`l2d-capability.js` 的能力报告 —— 把"这个模型缺什么"直接列出来（标准参数 10 项、面部参数 4 项、表情/动作/纹理/槽位），和我们 doctor 的思路一致，可以合并。

## 8. 关于「用 Rust / Zig 重构」

结论：**这一轮不建议；如果一定要，只把编译器做成 Rust→wasm/CLI。**

| 候选 | 语言收益 | 代价 | 判断 |
|---|---|---|---|
| 渲染循环 / 参数写入 | 几乎无（Cubism Web SDK 是 JS，60fps 跨进程只会更慢） | 每帧 IPC、双份状态 | ❌ |
| 表情/情绪数学 | 无（纯浮点，JS 足够） | 失去 esbuild 打包与共享类型 | ❌ |
| 轨道编译器/校验 | 中（纯数据变换、需要严格） | 多一层序列化/构建 | ⚠️ 只有想把校验同时给 Node + 浏览器 + 外部 Agent 用时才值 |
| 权威状态服务（跨窗口/跨进程/重启可续） | 高（并发、持久化、单一真源） | 要等第二个消费者（直播窗/手机端） | ✅ 以后做 |
| 现有 `pet-core` 的纯函数（韵律/心情/窗口几何/知识检索） | 已经这样了 | — | ✅ 保持 |

更准确的说法：jingyu 的贡献不是"用了什么语言"，而是**把"演什么"变成了可校验的中间表示**。这件事用 JS 做同样成立，而且和播放器共享结构更省事。

### 11.3 术语

| 词 | 含义 |
|---|---|
| FACS | Facial Action Coding System，面部动作编码；这里指 20 多个语义表情通道 |
| VAD | Valence（效价）/ Arousal（唤醒）/ Dominance（支配），三维连续情绪空间 |
| 轨道 track | 一个参数随时间的关键帧序列（`{id, start, duration, points}`） |
| 通道冲突 | 两个动作在时间重叠且控制同一参数 |
| 物理输出 | 由模型 physics3.json 计算写回的参数，直接驱动会被覆盖 |
| exp3 | Live2D 表情文件（`.exp3.json`），本质是"一组参数 + 混合方式" |
| overlay | 允许叠加在轨迹上的表情层（不独占） |
