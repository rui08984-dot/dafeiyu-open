# 框架设计：认知内核（2026-11-18）

> **一页总图**：世界感知（Phase 1 已有 + 2/3/4 设计）+ 电脑操控（planner/验证/grounding）+ 认知内核，
> 以及它们和现有进程/端口的所有权关系。
> **对齐**：`docs/架构总览-2026-11-17.md`（同一套进程/端口/所有权说法）、`ADR-001`（pet-core 无状态）、
> `ADR-004`（成本/缓存）、`ADR-006`（plan 分层）、`ADR-007`（验证/恢复）、`ADR-010`（记忆 v2）、
> `ADR-011`（目标栈/节拍）、`ADR-012`（技能沉淀）。
> **一句话**：新增的只有 `mind-kernel` 一个宿主插件与一批 oracle/闸门；**不新增进程、不新增端口、不改帧循环**。

## 2. 模块职责表

| 模块 | 进程/归属 | 只做 | 绝不做 |
|---|---|---|---|
| `world-sense` | 渲染层插件（已有） | 1s 采样、TTL 事实、五态活动机、每轮只写变化 | 调 LLM、决定说不说话 |
| Phase 2 源适配器 | 渲染层 + 8103（新增入口） | 浏览器/RSS/通知的只读事实，带 token/单源开关 | 抓正文、逐条摘要、直连外网 |
| `mind-kernel` | 渲染层插件（新增） | 目标栈、准入闸、30s 规则定向、pause/resume | 调 LLM、执行动作、改 plan 内容 |
| `dispatch/plan-store` | 渲染层插件（新增，ADR-006） | 持有 plan、diff、状态机、≤80 token 预算 | 维护目标生死、等模型 |
| 规划调用 | 同一个 LLM client（按需） | 首次分解、失败重规划（结构化输入） | 每步调用、输出 DAG |
| LLM 循环 | `llm-handler.js`（已有） | 消费计划行、产出下一步工具调用、打断 | 决定完成/停止、维护预算真值 |
| `dispatch` + grounding | 渲染层/Rust（已有） | 12 动作（底层 36 个）、四档阶梯、三层注入、前台校验、幂等回读 | 裸坐标乱点、后台乱跑 |
| `verify-contract` + oracle | 渲染层 + Node getter（已有+新增） | T1/T2/T3、外部状态断言、evidence | 读工具返回值、让模型自评 |
| `skill-library` | 渲染层插件（已有+扩展） | 技能候选/晋升/降级、pitfall、t=0 检索 | 执行未验证步骤、存不可重放动作 |
| `episode-store` | 渲染层（已有） | 对话片段卡片、游标不前进不丢数据 | 改写原文 |
| `user-facts`/`insights` | 渲染层（已有+ADR-010） | 双时态事实、反思结论、只 supersede | 删除记忆、无证据总结 |
| `speech-budget` | 渲染层（已有） | 日预算、90s 结算、accept_rate | 感知、决策 |
| `_probe/agent-eval` | 离线 Node | 确定性任务、oracle、故障注入、指标 | 进运行时、依赖 LLM 才能跑 |
| `pet-core` | Rust 常驻（已有） | 截图/窗口/键鼠/UIA/世界快照/知识检索 | 任何 goal/plan 状态、任何 LLM |

## 3. 数据流（谁喂谁）

1. **世界 → 内核**：`world-store.snapshot()` + `recentChanges()` 每轮一次；内核只读，不反写世界。
2. **用户 → 内核**：`InputRouter` 的意图事件；用户消息优先级最高，直接进对话主链，不排队。
3. **内核 → 计划**：goal 激活时创建 plan（ADR-006）；只有「首次/失败/偏离」三个触发点调规划 LLM。
4. **计划 → 执行**：每轮只把变化的 plan 行拼进最后一条 user 的易变尾巴；system/tools/历史一字不动。
5. **执行 → 世界**：动作经 `dispatch` → `pet-core`；T1 读前后状态差（dHash/UIA 摘要），不改动作语义。
6. **执行 → 验证**：子任务完成跑 T2；任务结束跑 T3；getter 只读文件/窗口/UIA/剪贴板/进程。
7. **验证 → 恢复**：T1/T2/T3 失败进五级阶梯；每上一档写 evidence；两条熔断按任务计数。
8. **任务 → 记忆**：成功写 task-episode；失败→成功写 lesson；重复两次独立成功写 skill candidate。
9. **记忆 → 内核**：只在 t=0 检索一次（技能+教训）；运行中最多在重规划时再检索一次。
10. **内核 → 表达**：执行中的动作不申请发言预算；只有「报告结果/发起 offer」走 `speech-budget.request`。
11. **评测 → 内核**：离线读同一 oracle/getter 与 `last-run.json`；不反向依赖运行时，不做「只出报告」的假评测。

## 4. 节拍表

| 节拍 | 谁 | 做什么 | 成本 |
|---|---|---|---|
| **1s** | `world-sense` | 四个便宜源采样 + 活动状态机 + 变化历史 | 3.8–4.2ms/秒（低功耗 122µs） |
| **15s** | `speech-budget.tick`（已有） | 90s 窗口结算 accepted/ignored/negative | 微秒级 |
| **30s** | `mind-kernel.arbiter`（新增） | 仅当有 goal：预算/活动门/熔断/优先级/安全点 | <1ms，0 LLM |
| **每轮** | `world-sense` + `plan-store` | 世界差分 ≤100 tokens + 计划差分 ≤80 tokens | 0–180 tokens |
| **每动作** | `verify-contract`（已有） | T1 效果判定、`action_sent` 禁重试 | L1/L2 已有 |
| **每子任务** | T2 断言（新增） | 声明式 getter+predicate | 8–40ms |
| **每任务** | T3 oracle（新增） | 外部状态三元组 + evidence | 一次调用 |
| **任务结束** | task-episode / skill candidate | 叙事、教训、候选技能 | 1 次 LLM（可搭车） |
| **按需** | 规划调用 | 首次分解 / 失败重规划（≤2 次） | ~600 in / 200 out / 次 |
| **≤4 次/天** | reflection（ADR-010） | 重要性累加触发，证据链 | ~6k in / 1.6k out / 天 |
| **1 次/天** | 今日简报（ADR-009） | top12 → 1 次 LLM | ~1.2k in / 200 out |

## 6. 三期落地路线（每期 1–2 周，带判据）

| 期 | 时间 | 交付 | 通过判据 | 明确不做 |
|---|---|---|---|---|
| **Phase 1 能验收** | W1–W2 | T2/T3 oracle + 5 条 getter + gold 解；`liar` 开关；no-change/循环熔断；`finish/fail/wait/ask_user`；infeasible 3 条 | liar 下 oracle 5/5 判失败；禁用按钮第 2 次换路；infeasible 3/3 主动失败且零副作用 | 不做 planner、不做目标栈、不碰 LLM 任务 |
| **Phase 2 有计划** | W3–W4 | `goal-store` + 30s arbiter + plan-store 差分注入 + task-episodes + 3 条 ≥8 步长任务 | 长任务 ≥2/3；步数 ≤gold×2；前缀缓存 ≥90%；重启后不重复副作用 | 不做技能自动晋升、不做 curiosity |
| **Phase 3 会变强** | W5–W6 | 技能候选/晋升/降级 + lesson 检索 + 6 条恢复任务 + 3 条长任务评测 + 同构 LLM runner | 同类任务第二次步数 −30%；污染样本 0；恢复 ≥3/4；误伤 0 | 不做代码生成、不做微调、不做多 agent |

> Phase 1 的 oracle 是 Phase 2/3 的前置：没有它，计划、技能、记忆全部无法验收（ADR-007 同一结论）。
> 每期结束更新 `progress.md` 看板与 `architecture.mmd`，并跑 `check-all` 的 fast 子集。

## 7. 与现有架构的对齐 / 不做什么

- **进程与端口不变**：宿主仍是 1 个 Electron 实例 / 8 个进程，不新增窗口、常驻服务或端口；
  `mind-kernel` 是渲染层插件，随宿主生命周期；`pet-core` 仍无状态。插件数 23→24，**对外工具面不增（仍 28 个）**。
- **世界感知不变**：Phase 1 的 1s/只写变化/易变尾巴纪律原样保留；Phase 2–4 只加源与评测，不改采样骨架。
- **电脑操控不变**：12 个对外动作、四档 grounding、UIA 优先、前台校验、幂等回读全部保留；新增的是 oracle 与四档控制动作。
- **记忆不变**：MemOS 仍是原文检索库；`insights` 不回写 MemOS；技能库与事实库分开（ADR-010/012）。
- **不做的**：常驻自主循环 / DAG / 多 agent 并行 / code-as-action / 图数据库 / 轨迹微调 / 每步 VLM。
