# 调研：Agent 记忆系统的评估与衰减

> 对象：`<project-root>` 的七源记忆（核心 / 用户记忆 / 事实 / 结论 / 记忆库 / 日记 / 对话）、
> `js/core/memory-usage.js` 的「兑现率」与「90 天 0 命中降权」。
> 日期：2026-11-22。方法：论文（arXiv/DOI）+ 开源实现（仓库文件/行号）+ 本项目代码/文档。
> 只写实际核到的内容；核不到的单列在文末。

## 结论先行

1. 业界（Mem0 / MemGPT-Letta / Zep / A-MEM / MemoryBank / MemoryOS / Cognee）对「这条记忆有没有用」仍以离线 QA 或检索指标为主；生产侧只有 Mem0 明确把 token 与 p95 延迟作为部署指标（Zep 报的是基准里的响应延迟），**在我们核到的材料里，没有一家给出比「片段命中」更可靠的廉价单条效用判据**——我们的兑现率应定位为「采用率代理」，不能单独作为降权依据。
2. 有明确参数证据的衰减只有三类：Ebbinghaus `R=e^{-t/S}`（MemoryBank：S 初始 1、每次召回 +1、t 归零）、`0.995/小时`（Generative Agents，半衰期 5.76 天）、`Heat=αN_visit+βL_interaction+γR_recency` 且 `R=exp(-Δt/μ)`（MemoryOS：μ=1e7 秒≈115.7 天，半衰期≈80.2 天，τ=5）；Mem0 用显式 `expiration_date`，Zep 用双时间轴「矛盾失效」，都不做时间衰减。
3. 我们最该补的不是更复杂的衰减公式，而是**统计口径**：`isDecayed` 目前以「首次注入」为锚点、且不要求最小注入次数，会把「一直在注入但很少被引用」误判成「无用」；应先改成「注入次数 ≥ N 且采用率上界低于阈值」，再加 5–10% 探索配额，避免「越不注入越不被用」的反馈回路。

## 证据

### 1. 业界怎么评估「这条记忆有没有用」

关键事实（逐条可核）：

- **Mem0 的「用上」判定是 LLM-as-a-Judge，不是生产埋点。** 论文明确说 F1/BLEU-1 对事实错误不敏感，因此加一个独立 LLM 按 factual accuracy / relevance / completeness 打分；这只是离线评测集上的指标（arXiv:2504.19413，§3.2）。
- **Mem0 的 OSS 版本没有自动衰减。** 当前 `main` 的 `project.update(decay=True)` 在 OSS 直接抛 `get_decay_feature_error_message(...)`；它支持的是每条记忆的 `expiration_date`（`YYYY-MM-DD`，过期后 `search`/`get_all` 默认隐藏），以及 ADD / UPDATE / DELETE / NONE 四操作。文件：`mem0ai/mem0` 的 `mem0/memory/main.py` 第 442–483 行（过期判定与 decay 报错）、第 760–790 行（`add(..., expiration_date=...)`）、第 2052–2135 行（`_update_memory` / `_delete_memory`）；`mem0/configs/prompts.py` 第 176–185 行（四操作定义）。
- **Mem0 保留了完整变更历史。** `_update_memory` / `_delete_memory` 都写 `db.add_history(memory_id, prev_value, new_value, "UPDATE"/"DELETE", ...)`（`mem0/memory/main.py` 第 2052–2135 行）。这比「只存当前值」更适合事后评估「这条记忆是否被改坏」。
- **Zep 用「失效」而不是「衰减」。** 双时间轴：`t_valid` / `t_invalid` 表示事实在真实时间上何时成立，`t'_created` / `t'_expired` 表示系统何时写入/失效；Graphiti 的边解析带 `invalidated_by` 参数。文件：`getzep/graphiti` 的 `graphiti_core/utils/maintenance/edge_operations.py` 第 429 行起 `resolve_extracted_edges(..., invalidated_by=...)`；论文 arXiv:2501.13956 §2。
- **Cognee 的「遗忘」是管理 API，不是自动衰减。** `cognee/api/v1/prune/prune.py` 只有 `prune_data()` / `prune_system(graph, vector, metadata, cache)` 两个手动入口（第 1–22 行）。
- **A-MEM 用「记忆演化/链接」而不是衰减。** `agentic_memory/memory_system.py`：`process_memory`（第 590 行）让 LLM 生成关键词/标签/上下文并建立链接，`consolidate_memories`（第 266 行）做整合，`search_agentic`（第 509 行）做多步检索；没有时间衰减项。
- **Letta 的 core memory 是「常驻块」，不是检索结果。** 文档原话：memory blocks 是 context window 中跨交互持久的结构化片段，「always visible - no retrieval needed」，以 XML-like 形式 prepend 到 prompt（`https://docs.letta.com/guides/agents/memory-blocks`）。这给我们一个直接可借的分层：核心/用户记忆应常驻，事实/结论/日记/对话才走检索与衰减。

### 2. 有具体参数的衰减 / 遗忘

| 方法 | 公式 / 机制 | 参数（论文原值） | 证据 |
|---|---|---|---|
| MemoryBank（2023，Ebbinghaus） | `R = e^(-t/S)` | `S` 首次提及初始化为 1；每次被召回 `S += 1`，并把 `t` 重置为 0；`R` 是保留率 | 论文《MemoryBank: Enhancing Large Language Models with Long-Term Memory》arXiv:2305.10250 §2.3 |
| Generative Agents（2023） | `recency = 0.995^(sandbox hours since last retrieval)`；最终分数是 recency / importance / relevance 的加权和 | 衰减因子 0.995/小时；importance 由 LLM 打 1–10 分；relevance 用 embedding cosine；三者 min-max 归一后加权 | 论文《Generative Agents: Interactive Simulacra of Human Behavior》arXiv:2304.03442 §4.1（Memory and Retrieval） |
| MemoryOS（2025） | `Heat = α·N_visit + β·L_interaction + γ·R_recency`；`R_recency = exp(-Δt/μ)` | α=β=γ=1；`μ=1e7` 秒（≈115.7 天，半衰期≈80.2 天）；MTM→LPM 的 heat 阈值 τ=5；检索 top-m 段=5，top-k 页=5/10；分段相似度阈值 θ=0.6 | 论文《Memory OS of AI Agent》arXiv:2506.06326 §3 / §4（超参数段） |
| Zep / Graphiti（2025） | 双时间轴 + 矛盾失效；不按时间衰减 | `t_valid`/`t_invalid`、`t'_created`/`t'_expired`；边可被 `invalidated_by` 标记 | 论文《Zep: A Temporal Knowledge Graph Architecture for Agent Memory》arXiv:2501.13956 §2；`graphiti_core/utils/maintenance/edge_operations.py:429+` |
| Mem0（OSS） | 显式过期日；无自动衰减 | `expiration_date` 为 `YYYY-MM-DD`；过期后默认从 search/get_all 隐藏；`decay=True` 在 OSS 报错 | `mem0/memory/main.py:442-483, 760-790` |
| Cognee | 手动 prune | `prune_data()` / `prune_system(graph, vector, metadata, cache)` | `cognee/api/v1/prune/prune.py:1-22` |
| A-MEM | 链接演化 / 整合；无时间衰减 | `process_memory`、`consolidate_memories`、`search_agentic` | `agentic_memory/memory_system.py:266, 509, 590` |

可直接用的数值结论：

- Generative Agents 的 0.995/小时很激进：`ln(0.5)/ln(0.995) = 138.28` 小时，即半衰期 **5.76 天**。它适合「今天的行为/位置」这类短期状态，不适合「用户叫什么、养了什么宠物」这类长期事实。
- MemoryOS 的 μ=1e7 秒是 **115.74 天**，半衰期 `μ·ln2 = 80.23` 天。我们的「90 天」正好落在它的半衰期附近；但 MemoryOS 是连续 heat + 分层淘汰，我们是二值标记。
- MemoryBank 的 `S += 1` 是最便宜的可解释强化：每次被引用就把强度加一、把「上次使用时间」归零；不需要 embedding，也不需要额外模型调用。
- Sleep-time Compute（2025，arXiv:2504.13171）：把「提前想好」放到离线，在 Stateful GSM-Symbolic / Stateful AIME 上以约 1/5 的 test-time compute 达到同等准确率，并可通过扩大离线计算再提升 13% / 18%。适合把记忆整合、链接、衰减重算移出对话链路。

### 3. 召回质量指标：哪些能在生产里算

| 指标 | 定义 | 成本 | 能否生产 | 证据 / 备注 |
|---|---|---|---|---|
| 采用率（我们的兑现率） | `used / injected`，按来源分桶 | 零额外模型调用；正则/子串 | 能 | 我们的 `memory-usage.js` 已实现；缺点是只认原样片段，偏保守 |
| 结构化自报 used IDs | 让模型在回复外额外输出 `used_memory_ids: [...]`，展示前剥掉 | 每次多几个输出 token | 能 | 思路来自 citation/attribution 评测（ALCE，arXiv:2305.14627；Attributed QA，arXiv:2212.08037）；需抽样校准 |
| 抽样 LLM 判定 | 每 N 轮抽 1 轮，让便宜模型判每条「used / not / contradicted」 | 1 次额外调用 / N 轮，且可离线批处理 | 能 | Mem0 的 LLM-as-a-Judge 是同类做法（arXiv:2504.19413 §3.2）；只用于校准，不进主链路 |
| 用户纠错 / 重复 | 「你忘了」「不是」「我说过」+ 同一事实再次出现 | 正则 + embedding，近零 | 能 | 工程信号，无需论文；适合做负样本 |
| 反事实留出 | 随机跳过 1–2% 的低风险注入，比较下一轮用户反应/任务成功 | 需要 A/B 与统计，样本量大 | 能但慢 | 因果效用；受反馈回路影响的采用率不能替代它（Chaney et al., arXiv:1710.11214） |
| 下游任务成功 | 有/无某条记忆时任务是否完成 | 最贵；要跑任务 | 只能抽检 | τ-bench 式 end-state 检查（arXiv:2406.12045）；适合季度校准 |
| 离线 context precision/recall | 需要标注的 ground truth | 中 | 不能直接生产 | RAGAS（arXiv:2309.15217）；适合回归集，不适合线上 |
| 注入预算 / 长度 | 每次注入的 token 数、条数 | 零 | 能 | Context Rot：18 个模型在输入变长时性能非均匀下降（Chroma 2025，`research.trychroma.com/context-rot`） |

补充证据：

- **LongMemEval** 把长期记忆拆成五种能力：information extraction、multi-session reasoning、temporal reasoning、knowledge updates、abstention；指标是 QA accuracy + memory recall（arXiv:2410.10813）。其中「knowledge updates」和「abstention」正好对应我们「事实 vs 结论 vs 日记」冲突与「不知道就说不知道」的场景。
- **MemoryAgentBench** 把记忆能力拆成四种：accurate retrieval、test-time learning、long-range understanding、**selective forgetting**（arXiv:2507.05257）。「选择性遗忘」是被单独评测的能力，不是删得越多越好；这支持我们保留「只降权不删」的底线。
- **Context Rot** 的实测：18 个模型（含 GPT-4.1、Claude 4、Gemini 2.5、Qwen3）随输入长度增加，性能「grows increasingly unreliable」；在 LongMemEval 上，focused prompt 明显高于 full prompt（`research.trychroma.com/context-rot`）。结论：七源全塞会稀释注意力，注入条数/ token 预算本身就是一个质量指标。

### 4. 本项目现状（代码级）

文件：`<project-root>\_incoming\my-neuro\live-2d\js\core\memory-usage.js`（535 行，2026-11-22 的 D5 实现）。

- 七源白名单与常量：`SOURCES` 七类、`DECAY_DAYS = 90`、`DECAY_MS`、`MIN_FRAGMENT_CHARS = 6`、`MAX_FRAGMENTS = 12`、`PENDING_TTL_MS = 10 分钟`、`MAX_ENTRIES = 8000`（第 33–47 行）。
- 片段抽取：按标点切句，取 12/10/8/6 字窗口；要求 ≥60% 非虚字，且不含「我知道了 / 我觉得 / 你可以」等通用壳（第 51–138 行）。这是高精度、低召回的设计，注释也明确「宁可漏记，不虚报命中率」。
- 注入记账：`noteInjected` 给每条 `injected += 1`，记 `firstAt` / `lastInjectedAt` / `batch` / `turnId`（第 313–351 行）。
- 结算：`noteUsed` 只在回复归一化后**原样包含**某个片段时 `used += 1`；有轮次绑定（A 轮注入、B 轮回复 → `stale-turn` 丢弃）和 10 分钟 TTL（第 367–420 行）。
- 衰减：`isDecayed(entry, now)` 的锚点是 `lastUsedAt`，没有 `lastUsedAt` 就用 `firstAt`；只要 `now - anchor >= 90 天` 就标记 `decayed`（第 170–177 行）。
- 权重：`weightOf(id)` 对 `decayed` 返回 **0.5**，否则 1（第 473–477 行）。
- 统计：`stats()` 按来源汇总 `injected` / `used` / `entries` / `decayed`，`finalizeBucket` 算 `rate = used / injected`（第 424–472 行）。
- **关键风险 1：锚点语义。** 一条记忆可能 100 天前首次注入、昨天还在注入，但从未被原样引用；`isDecayed` 仍会在第 91 天把它标成 decayed。它衡量的是「首次注入后 90 天没被引用」，不是「最近 90 天没被用」。应改为 `max(lastUsedAt, lastInjectedAt)`。
- **关键风险 2：没有最小样本量。** 只注入过 1 次、恰好那次没被引用，90 天后也会 decayed。应要求 `injected >= N`（例如 10）才允许降权。
- **关键风险 3：反馈回路。** `weightOf` 返回 0.5 后，如果未来接入召回打分，低分条目会更少被注入，从而更难被引用，`decayed` 永远无法恢复。Chaney et al. 的结论是算法性混杂会提高同质化、降低效用（arXiv:1710.11214）；需要探索配额。
- **关键风险 4：当前 `weightOf` 还没有消费方。** 全仓检索（排除 `node_modules` 与 `build/`）未发现 `weightOf` / `memory-usage` 的召回调用；模块头也写明「本轮不改召回打分」。所以上述风险目前是**潜伏的**，一旦接线就会生效。

### 最小落地顺序（建议）

1. **先修口径，不碰模型**：锚点 + 最小注入数 + Beta 上界 + 探索配额。这四件事都在 `memory-usage.js` 内部，能单独单测，不影响现有召回。
2. **再分层**：把「核心/用户记忆」从衰减池里拿出来，事实加 `valid_from/valid_to`；这一步会改召回，建议先用 shadow 模式（只记录不生效）跑一周。
3. **最后加校准**：`used_memory_ids` + 5% 抽样 LLM 判定；用校准结果决定是否把 `weightOf` 接进召回。

## 明确不适用（以及为什么）

- **直接照搬 Generative Agents 的 0.995/小时。** 半衰期 5.76 天；对「用户叫什么、住哪、养了什么」这类长期事实，一周就只剩一半权重，会把伴侣记忆变成金鱼记忆。它适合 sandbox 内的短期行为记忆。
- **每轮都跑 LLM-as-a-Judge。** Mem0 是在离线基准上做；我们单机本地服务，每轮多一次模型调用会把首响从百毫秒级推到秒级。只适合抽样、离线。
- **用「90 天墙钟」作为唯一判据。** 它把「没被注入」和「没被用」混为一谈；没有分母（注入次数）就没有统计意义。
- **让 LLM 自动删除记忆。** Mem0 的 DELETE 是「矛盾时删」，Zep 是「标记失效」；两者都保留历史/可追溯。我们应该只降权、标记 `superseded_by`，把物理删除留给用户显式操作。
- **上完整知识图谱（Graphiti/Cognee 全量）。** 七源、单用户、单机；双时间轴字段很便宜，但实体消解、图维护、LLM 抽三元组的复杂度不划算。先拿 `valid_from/valid_to` 和 `superseded_by` 两个字段。
- **把 RAGAS 的 context recall 直接搬到生产。** 它需要 ground truth；生产里没有。生产只能用采用率、抽样判定、用户纠错、反事实留出这些代理。
