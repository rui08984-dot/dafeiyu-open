# 全方向论文调研 · 视频陪看 / 声音理解 / 陪伴表达（2026-11-01 · 7 轮检索）

> 用户点名：一起看**不该靠多轮截图**；要男女声/人物声/人物情绪/音乐理解；要**整片情绪弧线**与观影人同步。
> 本文按「方向 → 学术现状 → 对我们管线的升级路径」组织，动作项全部标优先级。

## 一、视频陪看（一起看 v2 的三条升级路线）

### 现状
watch-screen：固定 12 帧截图 → 语言化汇总表 → 注入对话。弱点：时序对齐差、抓不到「剧情推进」、成本随帧数线性涨。

### 路线 A：**本地视频 = 直接读文件，一张截图都不用**（推荐先做，工作量小-中）
论文依据：V-STaR (2503.11495) / TimeWarp (2510.03955) 证明 Video-LLM 的时序理解短板靠「帧堆叠」救不回来，结构化时间线才是正解。
**动作**：watch-screen 检测到本地播放器时（窗口标题已有）→ 定位文件 → `ffprobe`/ffmpeg 抽：①场景切换点（scene detection）②内嵌字幕轨（SRT/ASS 直接读；PGS 走 OCR）③音频轨 → 送进我们**已有的** audio_loop 管线（SER+音乐分类+说话人）。
**产出**：完美时间戳的「场景+台词+情绪+音乐」四层时间线——比任何截图方案都准，且**零视觉 API 成本**（全本地）。这是成本控制静默版的完美功能。

### 路线 B：流媒体 = 流式视频对话模型（中期）
论文依据：**VideoLLM-online** (2406.11816)——LIVE 框架，连续视频流上做时间对齐的实时对话，Llama-3 底座 A100 上 10 FPS；开源可下。
**动作**：流媒体场景（B站/网飞，拿不到文件）保留屏幕捕获，但把「固定 12 帧」换成：①变化检测驱动的关键帧（已有）+ ②音频弧线（已有）+ ③可选：本地量化 VideoLLM-online（8B Q4 约占 6GB 显存，需 VRAM 判别门）做「当前片段字幕+预测下一步」。
**注意**：V-STaR 证明纯帧推理不可靠 → 我们的融合层（台词+音频情绪+关键帧）反而是论文认可的结构。

### 路线 C：整片情绪弧线（用户点名的「与观影人同步」）
论文依据：Emotion-LLaMA (2406.11161) 多模态情绪推理（音+画+字）；MERC 身份迁移 (2511.14969)。
**动作**：不追帧，追**弧线**——把 audio_loop 的逐句 SER 按时间窗聚合（平静→紧张→高潮→释然），叠加音乐情绪轨（HPCP 特征，2112.00702 证明调和音高类特征有效，essentia 本地可算），生成「情绪弧线时间轴」。她对话时带的不再是「画面摘要」而是「我们看到第 37 分钟，剧情正从压抑转向爆发，BGM 刚变弦乐」——这是「一起看」的灵魂。
**优先级**：P1（比 A/B 更能立刻改变体验，且几乎零成本——全在已有管线加聚合层）。
