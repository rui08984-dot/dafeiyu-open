## 2. 决策 1：执行层两条腿，由 plan 决定走哪条

| 腿 | 走什么 | 适合 | 不适合 |
|---|---|---|---|
| A 本地工具链 | 现有 28 工具 + dispatch 12 动作（UIA/SendInput/overlay） | 实时、GUI、需要她本人动作的任务 | 长链路编码、批量文件、终端命令 |
| B DSH headless | `dispatch_to_dsh` → bridge → `dsh --profile pet --json` | 编码、跑命令、批量文件、长任务 | GUI 操作（**硬拦截，已实现**）、需要用户中途审批的步骤 |

**规则**：plan 行带 `exec: 'local' | 'dsh'`；`classifyTask` 继续硬拦截 GUI 任务给本地；DSH 结果 `data.ok` 只代表「执行器说完成了」，**必须再过 T2/T3 断言才写 goal.done**（AAAAGENT 的 `accepted ≠ completed` 教训）。

**判据**：同一意图 10 分钟最多派 2 次（已有刹车）不退化；DSH 失败必须进 goal.lastError，不重发 `unknown` 副作用。

## 3. 决策 2：目标/计划两层归属

- **跨任务层 = 我们的 mind-kernel**（用户拍板自建）：
  持有 goal 生命周期、1 active + 3 queued、预算（maxSteps/maxLlmCalls/maxWallMs）、活动门、重启恢复、失败不重发。
- **单任务层 = DSH 原生插件**（pet profile 内）：
  `dsh-goal` / `dsh-tool-goal` / `dsh-command-goal` / `dsh-goal-round-driver` 管「这一次派活内部」的目标与续轮；
  `dsh-tool-ask-user` 管「它需要问人」；`dsh-commands` 管斜杠命令面。
- **边界**：mind-kernel 只注入「当前目标 + 计划行 + 预算」；不尝试读取 DSH 内部 goal 状态（跨进程黑盒）。
  DSH 的最终回执由 bridge 归一化成 `{ok, finalText, sessionId, tools, usage, error}` 再回写。

**为什么不全用 DSH 原生**：跨任务队列/重启恢复/活动门/预算必须活在我们进程里（DSH 会话是短命的，且 headless 每次新 session）。

## 4. 决策 3：DSH 接入契约（pet profile 隔离）

| 项 | 决定 | 理由 |
|---|---|---|
| profile | **新建 `pet`**，只给桌宠用；不动 headless/web/desktop | 用户拍板「隔离起来挺好」；插件叠加不外溢 |
| 插件 | goal/command-goal/tool-goal/goal-round-driver/ask-user/commands（按需最小集） | 用户确认 DSH 天生有这些，只是默认 bundles 没加载 |
| 调用 | `dsh --profile pet --json [--session-id] [--permission-mode X] --task?`（以实测为准） | 复用现有 dsh-dispatch.mjs 的解析 |
| 回传 | `ok / code / tookMs / sessionId / finalText / tools / usage / error / parseError` | 失败必须发声；parseError 不许当成功 |
| 权限 | 显式传 `--permission-mode`，回执记录实际模式；**默认保持现状不收紧** | 收紧会影响现有派活，等用户拍板 |
| 超时 | 杀整棵进程树（`taskkill /F /T`），记日志 | 防孤儿 DSH |
| 注入面 | 若可行去掉 `shell:true`（改 `cmd.exe /c` 参数数组） | 模型文本→本机命令的注入面 |

**判据**：pet profile 下 goal 工具可见（`--json` 事件里出现）；ask_user 在无人应答时的行为明确（fail-closed 或阻塞，不许静默）；现有 headless 派活零回归。

> **实测结论（2026-11-20，子代理 A）**：pet profile 已建成（`~/.dsh/profiles/pet`，headless 备份 `headless.bak-20261120`，零改动）。
> 重要修正：**headless bundle 本身就内置 goal / goal-round-driver / command-goal / plan-mode / commands / tool-goal / tool-todo / user-approval / permission-presets**——
> 不是「没有」，是默认没被我们的调用面用上。pet 只额外加了 `tool-ask-user` 并把权限三档补全（默认 `workspace-write`）。
> 实测：`get_goal` 可用（`{"goal":null}`）、`todo_write` 可用；`ask_user` 无 answerer 时返回 `NO_PROVIDER`（不静默）、timed 模式返回 pending；
> `workspace-write + ask` 下升级 `danger-full-access` 被拒（无 approval channel），显式 `--permission-mode danger-full-access` 才放行。
> **最大缺口**：ask_user 没有应答者、approval 没有 channel、headless 没有 `/plan` 命令入口——「有脑子和手脚，但没有嘴和耳朵」。
> **现状阻塞（不是本轮引入）**：comad 返回 QUOTA、zen-gate 8788 未启动、DeepSeek key 无效 → 真机云端派活暂时跑不通；工具行为用本地 mock 服务验证。
>
> **应答者（2026-11-20 深夜，主控实测）**：已补「耳朵」——本地插件 `dsh-pet-answerer` 挂在 pet profile 的 `cordis.patch.yml`（insert，不依赖 pnpm），
> 监听 `user-questions/request`，规则应答：读类允许 / 写·删除类拒绝 / 其余默认拒绝；`hostUrl` 非空时先问宿主（人工通道，接口已留、默认关）。
> 真机实测（新 key）：`ask_user_question` 返回 `{"answers":[{"id":"continue","selected":["取消"]}]}`，模型据此继续 —— **不再是 NO_PROVIDER**。
> 剩余缺口：宿主的「人工通道」还没接（`/dsh/ask` 路由 + 语音/字幕提问 + 等待回答），以及 approval channel（权限升级）仍无应答者。

## 5. 决策 4：记忆反思（ADR-010 落地）

- 触发：新 event 的 poignancy 1..10 累减，`≤0` 触发（阈值 **60** 起步，本地校准；不照搬 150）。
- 产出：`insights.jsonl` 一行 = `{id, text, evidence_ids[≥2], depth=1+max(证据depth), importance, created_at, cursor}`；`insights-cursor.json` 防重跑。
- 写入：只写盘，下一轮才注入（不本轮改人格/不改 system）。
- 巩固：只 append + `supersedes` 链接；不做 in-place UPDATE/DELETE；open_loop 7 天 TTL，raw facts 无 TTL。
- 评测：LongMemEval 36 题小集（recall_any@5 / recall_all@5 / nDCG@5 + stale_leak=0 + evidence_coverage=100%）。
- **判据**：每条 insight 的 evidence_ids 都能回溯；重启 cursor 不重跑；一天 ≤4 次反思（成本红线）。

## 6. 决策 5：全双工语音（先量后改）

1. **先量**：DevTools T0→T7 打点（VAD EOS/收尾录音/ASR 文本/提交 LLM/首 token/首段入队/TTS 首字节/onplay），30 轮×3 场景，报 p50/p90。
2. **改造 1（最高优先）**：拆双重静音（客户端 500→120–150ms）+ 合并窗口（2000→250–300ms）→ 预期 −2.05~−2.5s。
3. **改造 2**：首段流式播放（blob→reader/MediaSource）→ −0.3~−0.8s。
4. **改造 3**：本地语义 EOT（smart-turn v3 ONNX）替代固定静音 → −0.35~−0.5s。
5. **必修 bug**：`speech_activity` 200ms 心跳（修 `gap<200ms` 恒不成立→抢话从未触发）；假打断 pause/2s resume。
6. **硬约束**：不换 edge-tts、不换 SenseVoice；本地 TTS 永不碰。

**判据**：基线落盘；改造 1+2 后 p50 ≤2.5s；改造 1+2+3 后 p50 ≤2.0s、语义首响 p90 ≤2.2s；误切率不升。

## 7. 决策 6：世界感知 Phase 2（三条独立）

| 能力 | 路径 | 判据 |
|---|---|---|
| 浏览器 tab/URL | 自建轻量 MV3 扩展（host/title/audible/tabCount，不上 path/query）→ 8103 带 token | 停用 5 分钟无浏览器行；切 3 tab 3 行无重复；incognito 只写「隐私」 |
| RSS 简报 | 30–60 分钟拉取 → 剪枝 72h → 去重 → 打分 `0.40 recency + 0.25 interest + 0.20 source_trust + 0.15 novelty` → 前 3 | 同 feed 无重复 id；冷启动只按前两项；推过不重推 |
| 通知 | 现有 MSIX 稀疏包 + `userNotificationListener`；先 PowerShell 验 `RequestAccessAsync()`，再验 Electron，失败降级/关闭 | 纸面级（Status Ok + Allowed）+ 真机级（读到 ≥1 条真实 toast） |

**不做**：CDP 主路径、aw-server、轮询 wpndatabase、UIA 读操作中心。

## 8. 决策 7：实现语言（用户点名评估）

| 候选 | 结论 | 理由 |
|---|---|---|
| **JS/Node（现状）** | **主选** | mind-kernel/记忆/语音管线必须同进程消费 `world-store`/`addVolatile`/`action_sent`/`json-store`；换语言=跨进程两套真值+每 tick IPC，收益为零（30s tick 不是性能瓶颈） |
| Rust | 只保留在 `pet-core`（截图/窗口/键鼠/UIA/世界快照，1ms 级） | 高频低延迟才值得；把 goal/plan 放过去会违反 ADR-001「pet-core 无状态」 |
| Go | 否 | 新运行时/新发布链，与现有插件系统无交集；没有性能理由 |
| Python | 只用于已有服务（ASR/语义/嵌入） | 语音模型必须 Python；业务状态不放过去 |

**判据**：新增模块若 >5ms 且在帧循环/每动作路径，才考虑下沉 Rust；否则 JS。

## 10. 风险与未解

1. `dsh plugin --profile pet add` 需要 pnpm/网络；本机已有 `@deepseek-ai/*` 包在共享 node_modules，能否离线装待实测（子代理 A 负责）。
2. ask_user 在「无人值守 headless」下若阻塞，会挂住派活 → 必须设超时/降级（子代理 A 给结论）。
3. 计划生成（一次 LLM 产出 plan[]≤8）的 token 成本与质量未测；先用现有 provider 试 5 个真实任务再定阈值。
4. 浏览器扩展分发（开发者模式）与通知包身份（管理员注册）都需要用户动作，排在最后。
